# Buffer Android

Android Studio 打开上一级 `apps/android` 工程，运行 `buffer-app` 模块。

包边界和数据流见 [ARCHITECTURE.md](ARCHITECTURE.md)。

构建与检查（JDK 21、Android SDK 配置就绪后）：

```sh
bash gradlew :buffer-app:assembleDebug :buffer-app:lintDebug :buffer-app:testDebugUnitTest
```

命令在 `apps/android` 执行。安装包在 `buffer-app/build/outputs/apk/debug/buffer-app-debug.apk`。

## 快捷捕获

- 桌面长按空白处，打开小组件列表，添加“Buffer · 记下此刻”。点击“记文字”或“录语音”打开捕获面板。
- 启动应用并允许设备桥接和通知后，常驻 Buffer 通知提供相同的两个入口。通知权限被拒绝时，可以继续使用 Widget 或应用内入口。
- 语音面板中按住按钮开始录音，松开保存。首次授权麦克风后需要重新按住；点击 Widget、通知或授予权限本身不会开始录音。
- 文字面板关闭时保留草稿，旋转屏幕等界面重建会恢复草稿；这不等于原始捕获，需点击“保存”才写入事件库。
- 捕获入口可先离线使用。退出录音界面到后台会结束并保存当前录音；录音仍受已有的 30 秒/512 KiB 上限约束。

Widget 添加、锁屏通知点击、设备后台限制及麦克风权限交互需要 Android 设备验收。JVM 测试和 APK 构建不能代替这些验证。

## 添加 Vela：Fabric 配对与初始化

“我的设备”提供附近 BLE 发现和二维码定位入口。二维码仅携带公开身份，连接时 pin 该公钥；首次配对仍需在手机和 Vela 核对相同的 Fabric 配对码并确认。已绑定设备自动恢复认证通道，不重复展示配对码。配置和业务消息通过受权限约束的 ReliableMessages 交换，无需先建立设备间 IP 网络。

配对后可传递 Wi-Fi 配置，或使用设备已有网络；随后将手机已配置的 OpenAI-compatible 模型配置交给 Vela，由设备独立验证 LLM 与 ASR 后反馈状态。模拟器的 eth0 是已有网络，不伪装成 Wi-Fi 关联成功。退出添加页面不会关闭应用持有的 Fabric 通道；进程结束后的未完成输入由设备保留并在重新连接后重试。

具备有效配置和可执行条件的手机优先承担 Buffer 转写/分类，Vela 失联后可以接管。原始录音最终导入确认与处理完成确认分开，卡片副本和本地屏幕的五卡投影分开；手机任务提交由当前 Coordinator 租约保护。运行时证据与验收边界见项目 [Windows 双模拟器报告](../../../../docs/finals/05-runtime-verification.md)。

默认从同一源码树的 `:fabric-sdk` 构建，无需开发机绝对路径 AAR。仅在明确测试框架产物时，可用 `-PfabricSdkAar=/absolute/path/to/fabric-sdk-debug.aar` 替换；安装的 Hub 必须与 SDK 接口匹配。

## 旧固件兼容：配对与配网合并

手机从“添加设备 → 查找附近设备”扫描 S1 的 BLE 服务广播，首次发现无需家庭 Wi-Fi。选择设备后，在 Android 系统配对窗口输入 S1 屏幕上的蓝牙验证码；随后可选择“使用 S1 已保存的 Wi-Fi 并添加”，或填写新的 Wi-Fi 名称和密码后点击“连接 Wi-Fi 并添加”。前者不传网络凭据，设备会使用已有配置重新关联并取得地址；失败时可留在表单改填网络。S1 自行连接网络，手机验证对应请求的联网结果及局域网业务认证后才显示添加成功，无需再次输入配对码。

需开启手机蓝牙并授权附近设备权限；旧 Android 的扫描需要位置权限，新系统还可能请求局域网权限。手机需能通过局域网访问 S1。当前支持带密码的 Wi-Fi；密码只用于本次配置，不写入手机待添加记录。密码错误可在当前流程重试，取消会撤销待添加记录的认证资格。旧固件的局域网配对入口折叠在“连接旧固件设备”。

当前已通过模拟蓝牙传输的客户端测试，尚未进行 S1 与手机实机联合验收。滚动离开添加列表项、系统配对窗口遮挡和旋转重建不会主动关闭正在进行的 GATT 会话；退出 Activity 会关闭连接，应用进程被杀后不承诺自动继续。Wi-Fi 表单仅驻留内存，不随进程恢复。设备已保存绑定但手机丢失最终 BLE 结果时，新固件可在 LAN 握手提交与当前请求匹配的认证回执以恢复添加；需要手机桥接服务可达、待添加记录未取消且两端仍持有同一令牌。超时本身不是成功，旧固件无回执时不能走此恢复路径。

应用重开后，“添加设备”会显示未取消的待完成设备。点击“继续等待连接”启动局域网桥接服务，等待 S1 的认证回执；这不会重新发送 Wi-Fi 配置或绕过认证。若尚未完成配网，仍需重新扫描设备。点击“取消这次添加”撤销当前请求的授权；如果设备已经完成添加，会明确提示，不会自动解除正式绑定。

本机原始音频已接入独立的按对端发送账本、源事件回执门禁、blob 分片与重连核对，详情区分本机归档和曾获对端完整交付确认；原件和历史回执继续保留。数据库版本 28 增加派生元数据和有界补齐入口；版本 29 再增加 visibility-v1 的双进度、槽/填槽及发送 token 存储，不重写旧 Capture。两向可见性协议均已接入，受限位置保存不含原文指纹的槽，后续公开原文可继续传输；旧槽轮换补发，完整原文与 blob 仍分别确认。历史详情提示相关来源尚有保留位置。实现及静态回顾见参赛项目 `docs/finals/46-android-source-blob-sender.md`、`47-android-visibility-storage.md`、`50-visible-source-pull.md` 与 `51-visible-source-push.md`；未运行测试或构建，完整业务重放、父链及多成员仍未完成。
