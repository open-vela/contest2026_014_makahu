## 本次确认的具体问题

1. **周报统计口径有偏差**：`weeklySummary` 对完成任务使用 `cards.created_at >= since`，因此会漏掉“上周创建、本周完成”的任务；应按完成事件的时间统计。候选查询也未专门排除已经回答的问题，不能称为严格的未解问题精选。
2. **提醒动作未形成定时闭环**：通用 `remind` / `later` 是状态修改；需要明确提醒时间、持久任务、触发及取消策略。现有专注延后/跳过是另一套已实现功能。
3. **Android 网络服务停止不彻底**：`VelaBridgeServer.stop` 关闭监听 TCP/UDP，但没有跟踪并关闭已接入 Socket，也没有关闭线程池；快速重启还有旧线程清理共享 socket 的风险。上一轮被中断前只读了代码，尚未修复。
4. **安全传输未完成**：双方 HMAC 挑战证明已有实现，但初次配对和后续业务流量仍为明文，缺少业务消息完整性保护；不能将“认证成功”当作加密安全连接。

## 用户补充：手机主导配网

用户进一步要求将配对与配网合并。目标流程调整为：Android 通过 BLE 发现待添加的 S1 → 用户用 S1 屏幕验证码确认设备并建立安全配置通道 → 在同一向导填写 Wi-Fi 名称和密码，同时建立业务信任 → S1 自行连接 Wi-Fi → 手机自动验证同一设备和业务连接 → 添加成功。验证码只确认一次，联网后不再重复配对。详细交互和失败恢复要求见 `buffer_phone_openvela_docs.md` 4.5.1。

手机负责配置交互，Vela 保存配置并独立联网。首次配置通道必须在 S1 尚未接入家庭 Wi-Fi 时可用；现有局域网扫描不能承担首次配网。蓝牙或设备临时热点须先核对板级驱动与固件能力，当前不承诺已经支持。NSH 命令保留为调试/恢复入口，不作为正常用户的配网步骤。不得仅因手机端出现配网页面就标记配网完成。

### 实现推进：配网请求校验与分片协议

`buffer_enrollment.c/.h` 与 Android `VelaEnrollmentProtocol` 已实现请求的校验、编码和分片基础。JSON 字段固定为 `type=buffer.configure`、数值 `protocol=1`、32 位小写十六进制 `request_id`、1–79 字节合法 `phone_device_id`、64 位小写十六进制 `token`、`ssid`、`password`。手机必须在首次发送前持久化请求 ID 和随机令牌，重试使用同一组值；持久化发送流程尚待接入。

每次特征值写入为 `[offset:uint16be][total:uint16be][payload]`，JSON 总长最多 768 字节。MTU 23 时每次携带 16 字节有效载荷，无需依赖 MTU 协商成功。接收器限制总长和偏移、拒绝缺片/冲突重传、接受相同片段重复发送；重复末片不会再次触发完成。连接认证、接收超时和连接之间的隔离必须由后续 GATT 会话层执行，当前分片函数本身不证明这些条件。

Vela JSON 解析拒绝缺失、重复或未知字段、字段类型错误、非法身份、嵌入 NUL、超长或带控制字符的 Wi-Fi 信息。SSID 按字节限制到 32；密码为 8–63 字节口令或 64 位十六进制原始密钥。相同凭据校验已接入现有 `buffer_wifi_configure`，删除原来重复的宽松校验函数，修复 64 字节非十六进制密码仍能写配置的问题。

重要框架行为：`gatts_service.c` 的写入事件在调用应用 `write_cb` 前执行 `bt_sal_gatt_server_send_response`，因此应用回调返回值不能用来传达最终配网结果。后续须提供与 `request_id` 绑定的独立状态读取/通知，只有设备身份、网络连接及业务凭据确认后才能报告添加成功。

验证：新增 C 主机测试检查生产解码器和分片接收器；Android 新增 6 项测试覆盖 UTF-8 字节长度、非法 Unicode、凭据格式和所有 23–517 MTU 的请求重组。Android 构建、Lint 和 154 项测试通过。协议基础仍未接到 GATT 配置特征值，不能据此认定蓝牙认证、Wi-Fi 传输或统一添加闭环已完成。

### 实现推进：研究到期通知

到期结束会话时，同事务保存待通知会话 ID；调度器调用 NotificationManager，通过独立渠道提示记录本次发现，点击打开 Buffer。开始新会话清理旧通知状态，下次调度撤下旧通知。权限/渠道关闭或 notify 抛出 SecurityException 时不写成功回执，保存一分钟重试时间，并接入现有研究闹钟；重开可恢复。

睡前模式撤下已有研究通知并暂缓待通知，不将暂缓误记为已送达；退出后已送达者不重复提醒，未送达者可继续重试。用户手动结束/切换模式结束不产生到期通知。成功投递保存 RabbitHoleNotificationPosted；它表示 notify 调用成功，不证明用户已经看到或系统已响铃。通知采用固定 tag/id 和 onlyAlertOnce；外部通知与数据库提交不能原子化，崩溃或回执事务失败后仍可能再次调用 notify，不承诺严格恰好一次。
