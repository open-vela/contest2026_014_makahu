# Android 捕获源快照投影

日期：2026-10-25。任务 05 的业务投影第一阶段。只修改源码和文档并静态回顾，没有运行测试、构建、编译/语法检查、格式化、配置生成或设备。独立 Fabric 源仓库未修改。

## 本阶段实际范围

新增 `BufferSourceProjection`，由既有 `BufferSourceHistoryWorker` 在因果元数据与本机音频整理之后调用。直接消费接收事务已写入的 `source_event_projections`；每批最多八个候选、约 2 MiB 候选原文软预算。实体基线、旧删除检查、解析产生的中间表示属于额外工作，不把该软预算描述为整个调用的 I/O 或内存硬上限。

本阶段处理 Vela journal 的 `record_json` 捕获快照：CaptureCreated、CaptureRecordUpdated、CaptureTranscribed、ClassificationProposed、CardRecordChanged 和 LegacyCaptureSnapshot 等固定类型。相同名称的 Android 增量事件没有这个快照形状，保持 unsupported_type，不能按同名硬套解析。音频描述符仍由独立 blob 管线处理，不被当作完整捕获文本。

已知捕获状态可重建 Capture 的来源、原时间、模式、转写和分类视图；ready 快照复用现有纯解析器校验分类、稳定卡片 ID、关系与展示结构，生成真实 `cards` 行。助手、计时器、追问、专注、CRDT/副本、Android 增量事实等仍需专用适配器，此处不执行或假装已经投影这些类型。

## 事实与副作用边界

投影前通过持久 owner、实际接收覆盖、精确原文 SHA 和身份重新读取源事件，源事件 ID、父引用、时钟和 envelope 原文均不改写。离线整理使用已保存的授权历史，不要求当前网络连接；这不授予任何新通信或执行权限。

新 projector 不调用 `appendEvent`，不把远端事件复制进旧 `events` 执行事实表，不创建分类/转写、日历、健康、通知、提醒或回流任务，也不打开 payload 文件路径。新 Capture 的 blob_path/audio_format 留空，音频仍以源描述符与独立私有归档为准。来源状态的 reminder_pending/research_requested 只映射展示状态，不创建对应执行请求。

一次批次在 repository monitor 与 SQLite 事务内完成：业务行、实体绑定、投影状态与旧 processed 兼容证明共同提交；失败整批回滚，原文和待处理队列保留。纯 payload 校验失败单独记 invalid_payload，不把数据库/绑定损坏吞成“未知事件”。实体冲突在业务写入前预检，不留下半个 Capture 后再返回冲突。

## 本机编辑、旧视图及乱序

来源实体绑定 peer/source，保存单调 source_sequence、源字段基线与包含实体/来源身份的 SHA 校验。基线不包含本机用户的新意图。较早快照不能覆盖较新来源视图；相同位置重试按当前行与基线重新比对。

已由本阶段建立基线的行，只有仍等于上一来源基线的字段才随新快照更新。卡片分类/标题/摘要/动作/关系为一组，用户确认分类或修改其中字段后整组保留；状态单独比对。展示结构与原分段文本也遵守内容组保护，不用新来源展示覆盖手机已修改正文。回答、研究笔记、标签、外链和用户批准不由快照清空或伪造。

已有旧协议视图没有可靠来源基线时，首次绑定保留当前内容，并标记 legacy_preserved。明确的源删除、已有 SQL deleted、CRDT 墓碑或匹配的本地删除事实保持删除；不会由迟到 active 快照复活。旧删除检查按 capture 索引最多读取 33 条，超过页界而无法证明某张缺失卡片未被删除时，保守不重建该缺失卡片并保留覆盖提示；不会据此删除仍存在的其他卡片。删除状态会取消旧回流/提醒记录，实际通知撤下仍由现有本机 reconciler 处理，不重放历史提醒。

## 缺少父项与可见性

源快照自包含，因此在 missing_parent/waiting_parent 状态下可重建其可读取部分，但投影状态必须为 partial，不能记作完整恢复。父项后来到达，既有有界因果 fan-out 唤醒该投影，重新判断。已应用视图的因果元数据后来改变也会重新核对；无效时钟、损坏或被阻塞父链保留明确 blocked 状态，不执行历史动作。

详情同时显示因果状态和投影状态，区分已重建、部分重建、保留本机修改、已有较新来源视图、等待和需要核对。未知 schema/type 保留原文与未处理语义，不永久占住 pending 队首，也不把它们计作已完成业务投影。

## 旧 processed 通道交错

完整 ready 快照的精确 record SHA 与对应源事件形成单独兼容证明。旧 processed 通道后来送达时，再读该 owner 的实际源原文核对 SHA 与来源绑定，才可以返回 duplicate 并保存旧协议回执；仅凭 capture/card 存在不能确认交付。这只确认该快照已被历史和视图表示，不声明完整因果历史或音频已交付。

旧 processed 结果若在 pending 源快照与 ready 源事件之间到达，只允许补齐本阶段创建、来源/创建时间/模式相同且字段未被本机修改的 Capture。仍沿用旧通道原有事务和明确的本地重建事件，不将这些重建事件冒充远端源事实。已有卡片、其他来源或内容冲突继续拒绝，不能覆盖用户编辑。
