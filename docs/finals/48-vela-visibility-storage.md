## 固定旧前缀与可见性存储区

原实现使用连续序号作为原文数量，直接把槽塞入旧 head 会破坏时钟、索引计数和读取语义。因此保留旧 `remote/<source-hash>` 为固定原文前缀，并增加：

- `remote-visibility/<source-hash>/`：保留位置、填入的精确 envelope/指纹及待投影元数据。
- `remote-visibility-owners/<source-hash>.json`：固定 owner、基线、两种进度、真实原文数量、held 链及实际观察时钟。
- 独立的可见性写前意图、原文 staging 和可续跑索引迁移位置。

profile 记录的基线 B 是启用时既有旧原文前缀，之后不再由旧 receive 改写。C 为连续覆盖到的位置，H 为连续真实原文到的位置，N 为 B 之后实际保存的原文数量。必须满足 B≤H≤C、N≤C−B；没有 held 时 H=C、N=C−B，有 held 时 H 是第一条 held 之前的位置。

槽不产生原文 ID、原文 SHA、业务 Capture 或逻辑时钟。held 槽的 ID/指纹为空；filled 才绑定真实已提交原文。token 只按随机不透明标记校验，不把它当作隐文内容证明。所有路径均由 source 的 SHA 和有界数字序号生成，不接受来源提供的本机路径。

## 持久槽、填槽与原文身份

新增公开存储 API：visibility progress、reserve、receive、next；关闭源 journal 的构建返回 ENOTSUP，不虚报可见性支持。方法固定为 visibility-v1 存储契约，仍须由后续网络层显式协商后调用。

新槽或普通公开原文只能位于 C+1。较早槽的补发必须匹配同一 owner、source、sequence 和 token；重复槽幂等，变更 token 不覆盖。已保存的原文不会因新的槽请求而被删除或降级，original_present 本身仍不是新的完整原文交付证明。

填槽保留精确 envelope，校验 SHA、来源、序号、事件 ID、共同 wire schema 和两侧已知相邻原文的时钟关系。未知槽没有伪时钟，legacy_local 也不被套上不存在的 native 时钟。ID 与旧前缀、其他来源及可见性原文共用一个验证索引；外来事件仍不能占用本机 `evt_<local-source>_` 身份范围。

已占用位置收到不同 ID/原文是 conflict；已有 ID 在共同索引中消失、槽与原文状态矛盾、孤立文件或错误链指针是存储不一致，不当作可以覆盖的空位置。新位置在接受意图前检查没有原文、指纹或投影残留。held 不进入原文索引，不创建投影任务。

## 有界 held 链与精确恢复

held 槽用递增序号的双向链保存。追加只修改旧尾和新槽；填槽最多修改前后两条及目标槽，不扫描整份历史。首尾、相邻指针、owner 和槽状态均核对。filled 保留历史链接作为迭代 tombstone，不再计入 active held 数量。

next API 的 cursor 是下一条链指针，不能解释成 seq+1。一次最多跨过十六个已填 tombstone，EAGAIN 返回可继续的位置；cursor=0 开始一轮，返回最后槽后的零指针表示这一轮结束。后续网络控制器仍需安排周期重扫和公平补发，不能将一次遍历当作永久无工作。

每个 reserve/append/fill 使用独立写前意图：保存精确的 before/after 元数据、操作、序号、token、邻接位置，以及真实原文操作的 ID/SHA/时钟证明。原文先 staging；确认当前授权后持久化意图，再幂等完成文件、共同索引、待投影元数据、实际观察时钟、槽邻接关系和 profile 提交，最后清理意图及 staging。

恢复不使用 cJSON 的近似浮点比较判断计数身份，而是逐字段验证安全整数和预期变化。当前元数据必须精确匹配 before 或 after；操作类型、计数、首尾及原文证明均必须一致。原文缺失、冲突或前缀变化不会被跳过。旧接收意图先恢复，可见性意图再基于固定旧前缀恢复；不一致时保留证据并失败。

原文/指纹先保存、索引已写、邻接只更新一侧、profile 已保存但回执丢失等情况均通过同一意图重入。既有待投影状态只校验身份，不重置为 pending。持久重复确认和进度读取重写相同小型 profile，通过既有私有原子写入执行真实 backend barrier，处理 rename 已可见但之前同步失败的情况。不会因回执而删除原文或 blob。

## 原文计数、索引与读取兼容

共同 ID 索引的期望数量为“所有旧原文前缀数量＋所有可见性 N”，不使用 C 代替原文数量。原有有界迁移完成旧前缀后，再按持久 source/sequence 游标处理可见性区域：真实原文校验后入索引，合法 held 跳过。一阶段每批最多十六个位置、使用原有约 2 MiB 原文软边界；阶段交接让出 worker，不叠加两个完整批次后才返回。边界校验本身仍可能额外读取原文，不声称总 I/O 或设备耗时已经测量。

全局观察时钟只由实际原文推进；槽不增加时钟。来源元数据和目录交叉核对，真实原文数量与索引计数不符时不报告 ready。来源数量核对按目录线性遍历，没有为了每次累计数量而逐个排序重扫所有 owner，也不每次遍历全部事件文件。

普通本地读取、全局 ID 验证和已认证 owner 的 blob 原文绑定读取均可访问可见性区域中已经提交的真实原文；held 返回 EAGAIN，已提交原文丢失或指纹错误仍失败。旧 progress 继续报告 H+1，不把 C+1 冒充连续原文进度；启用 profile 后，旧 receive 返回 ENOTSUP，不能绕过槽约束继续推进旧前缀。

新增目录及写前/迁移元数据已纳入本机身份初始化和远端观察状态丢失检查。非空存储、缺失 owner、丢失 profile、缺失提交目录或旧基线不符时，不重新分配来源身份或重建为新流。只有没有已接受数据的空暂存目录可作为未完成准备保留。
