# Vela Material 3 Expressive UI 本地规范

版本：1.2 · 日期：2026-11-02 · 状态：设计与验收基线，待逐项实现和验证。

本规范面向 Vela 桌面、内置应用、系统浮层及 A2UI 生成界面。Gemini S1 是当前设备之一，不是布局的唯一尺寸。Android 配套应用共享语义、图标与品牌角色，同时遵守 Android 平台交互。

**本文规定目标行为，不代表现有代码已经满足。** 编写本文不涉及代码修改、构建或刷机。

阅读顺序按“基础 → 组件 → 系统组织 → 业务内容 → 验收”展开，避免把页面样式、图标资源与全局导航混在一起：

## 2. 产品原则与职责边界

### 2.1 桌面设备体验〔Vela 约定〕

桌面优先支持远看可读、近看可操作。默认画面突出时间、下一项安排和当前任务；次要信息通过层级、分组与详情承载。不得靠所有内容同时放大、全部使用主色或不断动画吸引注意。

表达性来自协调的色彩、字体、形状与动作。不能只给普通 M3 控件换大圆角就宣称完成 M3E，也不能把 Win8 的视觉直接替代 Material 风格。

### 2.2 Shell、应用与浮层〔Vela 约定〕

| 对象 | 自己负责 | Shell 负责 | 不允许承担 |
| --- | --- | --- | --- |
| `app` | 业务状态、内部路由、内容布局、局部 Dialog、最小可用尺寸约束 | 打开位置、宿主区域、全局导航、层级、焦点恢复与生命周期 | 操纵桌面根节点、计算屏幕绝对打开坐标、隐藏全局控件 |
| `systemOverlay` | 自身内容与操作状态，例如控制中心 | 边缘位置、遮罩、可用尺寸、输入阻挡与关闭顺序 | 自建第二套全局浮层管理器 |
| Widget / 磁贴 | 提交摘要、动作与内容尺寸需求 | 网格分配、排序、裁剪边界与滚动吸附 | 越过自身容器创建窗口 |
| Notification / Live Activity | 发布可识别的状态与动作 | 展示面、密度、排序、焦点与可见性策略 | 把展示坐标写进业务数据 |

应用声明至少包含稳定标识、类型、标题、入口路由、支持的布局约束和动作标识。上述字段是语义契约，不限定最终 C 结构或协议字段名称。内容可根据 Shell 提供的区域适配，不能反过来接管 Shell 的全局位置决策。

**Dialog 属于应用内部。** 应用管理 Dialog 的打开、关闭、确认与恢复，使用共享组件保证一致性。Dialog 不是全局窗口类型，也不是系统导航中的独立应用。系统浮层可以管理自身操作所需的局部确认。

### 2.3 返回、Home 与生命周期〔Vela 约定〕

1. 返回先处理最上层局部临时交互，再处理当前宿主的内部路由，最后退出应用或系统浮层。键盘、菜单和 Dialog 的拦截关系须明确，不能一次返回穿透多层。
2. 短按 Home 返回桌面。保留应用中可恢复的路由、阅读位置及业务任务；不得等同取消录音结果处理、计时器或同步。
3. 长按 Home 唤醒助手。长按成立后不得再触发短按；按压移出、取消、重复按键均须正确收尾。当前设备的 600 ms 阈值是本地映射，不是 M3 官方参数。
4. 关闭界面、隐藏通知、完成任务、取消任务必须分别建模。返回与遮罩关闭不得暗中提交或取消业务。
5. 应用切换、旋转、浮层覆盖和进程恢复都依稳定标识重建状态；失效数据须明确显示，不得伪装恢复成功。

## 3. Design Tokens：统一设计变量

主来源：S2–S8。以下集中管理方式为 Vela 约定。

| 分类 | 必须表达的语义 | 禁止的分散写法 |
| --- | --- | --- |
| Color | surface、onSurface、primary、onPrimary、error、outline 等角色 | 页面各自发明“按钮绿”“弹窗白” |
| Typography | display / headline / title / body / label 与 emphasized 角色 | 同一用途在不同页面随意指定字号 |
| Shape | 系统圆角角色与组件形状映射 | 所有东西都套同一个药丸圆角 |
| Space / Size | 内边距、间距、触摸区、布局约束 | 把一个设备的像素值散布到各页面 |
| Motion | scheme、spatial / effects、fast / default / slow | 每个页面自行决定一套缓动与时长 |
| Glyph | 字体链、图标家族、光学尺寸、渲染策略 | 混用 Unicode 图形、emoji 和不同图标库 |
| Elevation / State | 表面层级、状态层、焦点与禁用表达 | 仅凭加深底色表达所有状态 |

组件消费角色；页面组合组件。确有特殊展示需求时，增加有用途说明的局部角色，不能用局部数值绕过共享体系。主题切换应更新角色映射，而非遍历页面逐个补颜色。

### 3.1 变量登记与依赖方向〔Vela 约定〕

每个共享变量必须记录名称、语义、单位、明暗主题或状态变体、来源版本及降级方式。基础值映射到语义角色，再由组件引用；页面只选择适用角色。`primary` 不是固定 RGB，`labelLarge` 不是固定字体文件，`fast.spatial` 不是固定毫秒数。

设备档案仅定义逻辑 DPI、安全区域、字体资源、输入能力和绘制能力。内容数据不得携带设备绝对坐标。统一主题更新后，已打开的应用、浮层、Dialog 和增量生成的 A2UI 节点必须使用同一版本；不能出现新旧字体或颜色长期混用。

字体近似、动效降级、阴影替代等例外须登记“原角色 → 实际映射 → 原因 → 影响 → 验证范围”。存在替代映射时，不得把对应原始能力记为精确实现。

## 4. Layout：dp、sp 与自适应

主来源：S6。嵌入式换算和桌面方向为 Vela 约定。

### 4.1 单位与换算边界

- 布局几何、间距、圆角、触摸目标及图标视觉尺寸使用 **dp**；文字字号使用 **sp**，支持字体缩放。
- `px = round(dp × logicalDpi / 160)`；文字使用 `round(sp × logicalDpi / 160 × fontScale)` 选择或生成相应字体。行高随文字角色缩放。逻辑 DPI 须经设备映射确认，不能把像素分辨率直接当 DPI。
- 仅在布局到 LVGL 坐标、字体栅格化及图标栅格化的边界换算。布局中重复换算会造成尺寸漂移。
- 帧缓冲分辨率、图像原始尺寸、像素格式、stride、G2D 地址与裁剪边界仍按实际像素和字节计算，不能机械改成 dp。
- 对齐相邻边界时使用同一取整策略，避免逐项取整累积出缝隙。1px 光栅对齐属于渲染处理，不改变控件的 dp 语义。

以 130 logical DPI 为例，48dp 约为 39px，24dp 约为 20px。这只是换算示例，不是要求所有设备使用 130 DPI。

### 4.2 约束与响应

必须同时考虑可用宽度、可用高度、系统保留区域、文字缩放和输入方式。不能只用“横屏/竖屏”决定全部布局，也不能用缩放整棵 UI 的方式适配。

Android 窗口尺寸分类可作为参考，但不是嵌入式设备的机械分界线。小尺寸横屏也可能属于窄窗口；不能为了套用手机断点而在 S1 上挤出双栏。双栏只有在两栏分别满足内容与触摸要求时才能启用，否则回退单栏。

布局变化按以下顺序处理：重新分配空白与间距 → 内容换行与重排 → 改变栏数/控件排列 → 把次要内容移入详情。不得优先缩小正文和触摸目标。

### 4.3 间距、可读区域与固定操作区

Vela 基础间距采用 4、8、12、16、24、32dp 角色，分别用于紧密关联、组件内部、分组和区块留白；这是本地映射，不代表官方只有这些间距。密度变化应按角色调整，不能破坏触摸目标。

应用标题与必要导航、主要操作应有稳定区域，长内容在内容区滚动。不得把唯一返回或停止按钮放到长内容末尾。阅读区域限制合理行长；宽屏增加留白或相关分栏，不把单段文字无限拉宽。

旋转、窗口变化和数据增量更新后，保持选中对象、编辑状态和阅读锚点，不能回到第一页或自动滚到最新内容。

### 4.4 密度与放大验收〔Vela 约定〕

至少覆盖 100%、125%、150%、200% 字体缩放；分别检查窄宽度、低高度与宽屏，不能只把同一分辨率的截图等比放大。放大文字不改变设备逻辑 DPI，也不要求图标和全部留白同比放大。

固定栏的高度应由内容与触摸约束计算。高度不足时将相关操作重排或放入可达的菜单，内容区允许滚动；不能用固定像素高度裁掉放大后的文字。输入法、录音条、系统提示等占用区域由宿主统一扣除，不允许每个页面重复预留一遍。

## 5. Typography：文字角色与阅读

主来源：S3。中文字体选择与角色使用为 Vela 约定。

官方字体系统包含 display、headline、title、body、label 五类，以及 baseline 和 emphasized 两套共 30 种样式。实现必须保留这五类语义，并明确所用组件映射；不能只用“大小号字体”替代角色体系，也不要求每个页面展示全部角色。

| 角色 | Vela 用途 | 使用约束 |
| --- | --- | --- |
| Display | 时间、关键倒计时等少量焦点信息 | 不用于普通按钮、长文本或所有卡片标题 |
| Headline | 应用页或重要内容的主标题 | 控制数量，避免与桌面时钟竞争 |
| Title | 页面栏、卡片和分组标题 | 同层级保持相同字体角色 |
| Body | 助手回复、日程说明、菜谱步骤与正文 | 保证完整中文、换行和持续阅读 |
| Label | 按钮、菜单、字段、状态标签 | 不得为塞入按钮随意降级成极小注释 |
| Emphasized 变体 | 有限的重点或重要交互 | 使用对应强调角色，不把整页统一加粗 |

字体角色定义必须包括字体链、字号、行高、字重、字距和缩放策略。中文可以使用 MiSans 等有合法授权且覆盖完整的字体，不要求照搬西文字体；必须校准中西文混排的基线、数字与标点。

按钮文字按字体度量和内容盒对齐，不能按某几个汉字的可见墨迹逐个偏移。“历史”与相邻按钮应共用高度、文字角色、内边距和对齐规则。图标文字按钮须同时校验光学居中和文字基线。

正文按段落与语义组织，避免一整屏同级文字。主要动作、错误原因和关键时间不能靠省略号隐藏；摘要截断后必须提供可达的完整详情。流式更新不打断用户正在阅读的位置。

| Label small | 11 / 16 | 500 / 0.5 | 700 / 0.5 |

Vela 默认映射：桌面时钟使用 Display；应用标题使用 Title large 或 Headline small；卡片标题使用 Title medium；正文使用 Body large，密集的次要说明使用 Body medium；主要按钮使用 Label large。标题层级和信息密度决定选型，不根据页面名字另造字号。同一操作组必须统一角色。11sp / 12sp 的小标签不能承担主要正文或唯一操作说明。

所需字重缺失时允许登记近似映射，但不能静默用 600 代替所有 500 / 700 后声称字重完全一致。字距精度、行高和中西文基线亦须列入实际渲染检查。

## 6. Glyph：字形、字体链与 Material Symbols Rounded

主来源：S3、S4。字体继承检查与栅格策略为 Vela 约定。

### 6.1 文字字形与缺字回退

- 根节点、Tileview、应用宿主、系统浮层、Dialog、菜单、输入框、按钮、动态 A2UI 标签都必须获得有效的字体角色。不能假设根节点设过中文字体，主题创建的新宿主就一定继承。
- 字体文件“加载成功”与“覆盖所需字形”分别验证。字体链应覆盖常用中文、拉丁文、数字、全角/半角标点；缺字须继续回退到有对应字形的字体。
- 不允许把只含拉丁文的默认字体当作中文加载失败后的成功结果。无法覆盖时，应记录可定位的字体错误，并使用可读替代文本；不能让整页显示方框而继续静默运行。
- UTF-8 截断必须保持编码完整；长度计算、光标和删除应按字符/字素语义处理，不能按字节破坏中文或组合字符。
- 不支持的 emoji 不得承担唯一操作含义。用户内容的特殊字符可以使用受控替代显示，不能借此混入另一套 UI 图标。

### 6.2 图标来源与轴

所有产品 UI 图标统一使用 **Material Symbols Rounded**。禁止混用 Outlined、Sharp、emoji、私用区字符或临时文字图案。新增图标须登记语义名称、官方来源版本与授权信息；同一动作在全系统使用同一图标和文案。

| 轴 | 含义 | 本地使用原则 |
| --- | --- | --- |
| FILL | 轮廓与填充状态 | 默认轮廓；选中可用填充，不能作为唯一状态提示 |
| wght | 笔画重量 | 保持同一界面一致；不能随意混合粗细 |
| GRAD | 不显著改变占位的笔画微调 | 有实际对比与可读性需要时集中调整 |
| opsz | 面向显示尺寸的光学设计，官方范围 20–48 | 依据预期视觉尺寸选择；不是最终位图像素分辨率 |

默认轴组合应集中配置并固定资产来源。若现有资源以 wght 400、FILL 0 为基线，可以作为迁移起点；这不是所有场景都必须使用的官方组合。

### 6.3 清晰度与图标占位

图标以目标 dp 换算后的实际像素尺寸栅格化，使用可靠抗锯齿。优先缓存需要的原生尺寸；禁止先把低分辨率图标放大，再重复缩小。高 DPI 需要更大像素资产，不是把 opsz 当作像素值。

24dp 可作为常用图标视觉尺寸，触摸容器仍至少 48dp。视觉盒、触摸盒和字体基线分别定义。不得依靠放大位图填满触摸区，也不能让透明触摸区覆盖邻近操作。

图标状态颜色来自语义角色；禁用、选中、按下与焦点均须可辨识。只有图标的按钮必须有可访问名称，并在必要时提供可见说明。

### 6.4 Glyph 资源契约〔Vela 约定〕

Glyph 分为文字字形与 UI 图标两条资源链：文字依字体覆盖与排版；图标依语义名称和 Rounded 资产。不得依靠普通中文字体碰巧包含某个符号来提供 UI 图标。6.2 禁止的是临时把私用区字符当图标替代品；使用官方图标字体时，其经过版本登记的官方 codepoint 映射可以作为渲染细节，不得变成业务标识。

| 资源 | 必须记录 | 失败处理 |
| --- | --- | --- |
| 文字字体 | 家族、文件版本/摘要、授权、覆盖范围、字重、回退顺序 | 回退到覆盖所需字符的字体；仍失败时提供可读提示并记录缺口 |
| Rounded 图标 | 语义名、上游 commit、SVG/字体来源、摘要、轴值、视觉尺寸 | 保留动作的文字名称和触摸容器；不显示 emoji 或原始 ligature 名冒充图标 |
| 栅格缓存 | 图标资源、实际像素尺寸、轴值、像素格式；预着色时还包括颜色 | 按预算淘汰并重新生成；不使用已释放缓冲区或持续放大旧小图 |

当前图标资产基线为 `third_party/material-symbols/sources.json` 登记的官方 commit `27e9ef1dbeedc13d682fece4a58e1eda4cb0961a`，Rounded、wght 400、GRAD 0、FILL 0、opsz 24。它说明当前选定资产，不限制以后登记其他光学尺寸或选中态资产。变更轴值必须确认源资产支持；不能仅改清单而继续使用相同轮廓。

方向性动作按语言方向处理，时间、媒体、品牌或具有固定现实含义的图形不机械镜像。返回使用返回语义，关闭使用关闭语义，更多操作不能复用设置图标。图标按钮的可访问名称来自动作语义，不能直接使用文件名。

清晰度验收必须查看目标设备像素下的原图：轮廓连贯、同组笔画重量一致、透明边缘无色晕、图标与文字未重复缩放。以 130 logical DPI 为例，24dp 的目标约为 20px；这时仍应使用对应光学设计，不能把“原 SVG 是 24”误解成永远缓存 24px 位图。缺字验收同时覆盖静态标签、动态回复、按钮、菜单、输入框与异常回退界面。

### 6.5 动作语义目录与更新规则〔Vela 约定〕

下表固定动作含义与默认 Rounded 图标名；它是设计映射，不表示当前资产已全部打包。缺少资产时保留动作文字，新增图标须完成 6.4 的来源登记。

| 动作 | 默认语义名 | 必须区分的含义 |
| --- | --- | --- |
| 返回 / 关闭 | `arrow_back` / `close` | 返回上一级与关闭当前临时交互分别处理 |
| 更多 / 设置 | `more_horiz` / `settings` | 显示动作集合与进入设置目的地不同 |
| 历史 / 日历 / 待办 | `history` / `calendar_month` / `checklist` | 目的地名称保持稳定，不随页面改变图标含义 |
| 录音 / 停止录音 | `mic` / `stop` | 图标反映实际采音状态，准备中不假装正在录音 |
| 播放 / 暂停 / 继续 | `play_arrow` / `pause` / `play_arrow` | 与任务实际状态绑定；可访问名称说明正在操作哪个任务 |
| 新增 / 编辑 / 删除 | `add` / `edit` / `delete` | 删除不是完成，关闭不是删除 |
| 刷新 / 重试 | `refresh` | 文案说明刷新内容还是重新提交失败操作，防止重复副作用 |
| 完成 / 警告 / 错误 | `check_circle` / `warning` / `error` | 状态图标不自动变成可点击操作；必须有文字说明 |

资产升级以整套来源与缓存版本为单位。保留语义名，核对轮廓、轴值、授权和尺寸，再使旧栅格缓存失效；不在会话中混用两个未登记版本。字体子集必须包括静态文案及允许的动态内容范围；任意中文回复不能只依赖静态文案子集。字体资源重载后要重新应用文字角色并核对测量，不能只换文件路径。

字体的字重轴与 Symbols 的 wght 轴是不同资源的属性，不按相同数字机械配对。官方指南可能新增字体轴；只使用当前固定资产明确支持的轴，不因网页 API 支持新轴而宣称仓库旧 SVG 具备该能力。

## 7. Color、Tone 与 Elevation

主来源：S5、S7。桌面静态展示策略为 Vela 约定。

颜色按语义角色成对使用，例如 primary/onPrimary、surface/onSurface、error/onError。正文、图标、边框、选中态、状态层分别有对应角色；禁止每个页面自行混色，或用同一个主色填满所有容器。

信息层级主要通过文字、空间、容器与内容组织建立。色彩、表面色阶、描边及必要的阴影共同表达层级；不得只靠加重阴影区分前后，也不能因设备阴影效果差而让浮层与桌面融为一体。

普通文字按至少 4.5:1、符合大字条件的文字及必要非文字图形按至少 3:1 的适用规则检查对比度。大字条件使用可访问性标准的定义，不能把某个 sp 数值不经换算直接当作 WCAG 的 pt 条件。禁用态按相应例外处理；可操作内容不能为了“柔和”而降为不可读。

重要状态必须同时有文字、图标或形状提示，不能只靠颜色。透明叠加后的实际背景也要检查对比度。主题与屏幕亮度是不同层次，深色主题不能被当作背光控制已经实现。

### 7.1 表面与状态的映射〔Vela 约定〕

桌面背景使用 surface 系列，磁贴和应用容器使用选定的 surfaceContainer 层级；主要动作使用 primary/onPrimary，次要动作使用相应 container 或描边角色。局部错误使用 error 系列。控制中心、菜单与 Dialog 的表面须在叠加后仍能与背景区分；遮罩是输入和前后关系提示，不能替代容器边界。

Elevation 表达表面关系，不是任意 z 坐标。阴影、色阶与描边的降级由共享组件处理；Shell 的层级顺序仍由导航模型决定。状态层叠在正确的组件容器内，不能把 pressed 的颜色写回 normal 样式，也不能让 disabled 覆盖焦点清理逻辑。

## 8. Shape：圆角与表达性形状

主来源：S5、S8。

组件应使用对应的系统 shape 角色和组件映射，不统一套一个半径。M3E 扩展包含 large increased 20dp、extra large increased 32dp、extra extra large 48dp；完全圆角使用 full 语义。新增角色不意味着所有卡片都应该使用最大圆角。

| Shape 角色 | 圆角基线 |
| --- | --- |
| none | 0dp |
| extra small | 4dp |
| small | 8dp |
| medium | 12dp |
| large | 16dp |
| large increased | 20dp |
| extra large | 28dp |
| extra large increased | 32dp |
| extra extra large | 48dp |
| full | 根据当前容器形成完全圆角，不固定为某个大像素数 |

卡片首先选择适合用途的 filled、elevated 或 outlined 变体，再确定形状与表面层级。桌面磁贴作为本地组合容器，可以定义独立 token，但须说明与卡片角色的关系，不能让每张磁贴自由决定外观。

特殊形状用于少量重点内容或反馈，不替代标准操作图标。内外嵌套容器需协调圆角与间距，文字、焦点框和触摸反馈不得被圆角裁掉。按钮形状随组件类型、尺寸和状态选择，不能把菜单项、卡片与按钮全部做成长药丸。

Vela 的桌面磁贴默认采用 large 形状角色，应用内普通卡片使用 medium；重点容器可以选 increased 角色，选择理由与间距一并登记。它们是本地组合映射，不是官方对所有 Card 的统一规定。组件原有的形状状态规则优先于笼统的页面圆角。任何形变都不得改变点击动作归属或让相邻触摸区重叠。

## 9. Motion：动效系统

主来源：S2、S7、S10。LVGL 映射、桌面吸附和资源策略为 Vela 约定。

### 9.1 统一物理与角色

默认采用 Expressive motion scheme。运动按 **spatial** 与 **effects** 分开，各有 fast / default / slow 角色。弹簧使用刚度、阻尼和初始速度等参数；不能把这些角色简单理解成所有场景分别固定播放几百毫秒。

具体参数以固定版本的官方 specs 为来源，在 LVGL 的实现中记录单位转换、积分方式、稳定条件和回退策略。不能把另一平台的参数原样搬入不同物理模型后仍称为相同效果；若只能近似，应明确记为近似实现。

| 场景 | 空间角色 | 效果角色 | 行为要求 |
| --- | --- | --- | --- |
| 按钮、选择状态与短反馈 | fast spatial，确有形变时使用 | fast effects | 即时确认按压，不等待业务结果才反馈 |
| 应用打开、返回与容器过渡 | default spatial | default effects | 保持来源关系，完成后焦点可用 |
| 控制中心与菜单 | 按规模选择 fast/default spatial | fast effects | 遮罩、位置与输入策略同步 |
| 桌面滚动吸附 | 手势速度驱动的 spatial | 必要时使用 | 接续当前速度，落到合法锚点 |
| 内容增量与状态切换 | 通常避免整体位移 | fast/default effects | 保留阅读位置与操作目标 |
| 大范围重点变换 | 有理由时使用 slow spatial | 配套 effects | 不把所有日常操作都拖成长动画 |
| 常驻时钟、任务等待 | 默认静态 | 仅必要状态更新 | 不用持续装饰动画占据桌面与算力 |

### 9.2 连续性、取消与减弱动态

动画必须允许打断和重新定向，从当前状态继续，不能反复从起点重播。拖动释放后延续合理速度；再触摸时应能接管。空间过冲不得造成内容越界、错误点击或焦点丢失；颜色、透明度等效果值必须保持合法范围。

提供减弱动态策略：减少大幅位移、形变和过冲，必要时以短暂淡变或直接状态切换替代，同时保留因果关系。不能以关闭动画为由移除必要的状态反馈。

输入不能因装饰动画长时间锁住。不能播放假的进度、提前成功动画或用动画掩盖网络与存储等待。动画结束仅代表视觉结束，不代表业务结束。

### 9.3 动效登记与实现边界〔Vela 约定〕

每条动效必须登记触发条件、起止状态、目标属性、scheme / token、控制者、打断方式、减弱动态替代及对象销毁处理。Shell 管应用和系统浮层的过渡；组件管理自身按压/选择反馈；业务层只发布真实状态，不等待动画回调才提交核心任务。

| 属性 | 使用规则 | 边界与验收 |
| --- | --- | --- |
| 位置、尺寸、圆角、旋转 | spatial，可在适用场景有过冲 | 绘制边界、触摸区域和裁剪随当前画面保持一致；不得穿过受保护区域 |
| 透明度、颜色等视觉效果 | effects，无过冲 | 始终钳制在合法值域，透明元素不得遗留输入拦截 |
| 手势拖动、滚动吸附 | 直接跟随手势，再衔接速度 | 再触摸即接管；数据更新后落到仍有效的稳定对象 |
| 布局重排 | 内容约束优先，必要时过渡 | 旋转、字体放大时先得到合法布局，不能用动画掩盖裁切或错误锚点 |

弹簧适配必须记录质量假设、刚度/阻尼比、速度单位、时间步长、位置与速度收敛阈值及最大运行边界。效果弹簧不得沿用空间过冲。低帧率下按实际时间推进并限制数值发散，不能用“帧数固定”导致不同设备速度不同。

无法使用弹簧时，官方提供的曲线近似只适用于不含手势和打断的简单动画；不得据此实现拖动释放、快速反向打开或桌面吸附。静态近似可引用 S2 specs 中 Expressive 的以下基线：

| 角色 | cubic-bezier(x1,y1,x2,y2) | 参考时长 |
| --- | --- | --- |
| fast spatial | (0.42, 1.67, 0.21, 0.90) | 350ms |
| default spatial | (0.38, 1.21, 0.22, 1.00) | 500ms |
| slow spatial | (0.39, 1.29, 0.35, 0.98) | 650ms |
| fast effects | (0.31, 0.94, 0.34, 1.00) | 150ms |
| default effects | (0.34, 0.80, 0.34, 1.00) | 200ms |
| slow effects | (0.34, 0.88, 0.34, 1.00) | 300ms |

上述毫秒数是近似曲线参考，不是弹簧的固定持续时间，也不是业务允许阻塞的时间。若 LVGL 内置路径无法准确表达该曲线，须登记实际替代，不得仅因时长相同就声称曲线一致。

### 9.4 生命周期与审核场景〔Vela 约定〕

打开过程中返回、关闭过程中重新打开、连续切换对象、拖动中数据删除、吸附中旋转、动画中字体缩放及页面销毁都必须正确收尾。回调绑定当前对象和状态版本；已销毁页面的完成回调不能重新显示遮罩、移动焦点或操作复用后的对象。

减弱动态至少覆盖应用过渡、控制中心、磁贴变化、进度装饰与图标形变，并可在会话中切换。减少动态后返回、焦点、成功/失败反馈仍须完整。可见性降低或界面隐藏时停止无必要的循环动画，业务计时继续由任务域维护。

### 9.5 Expressive 弹簧参数基线

参数取自 1.4 的 AndroidX `ExpressiveMotionTokens v0_14_0` 快照。`MotionScheme` 将源字段 Damping 传给 `dampingRatio`；下表为无量纲阻尼比 ζ，不能当作阻尼系数 c 使用。刚度保留 Compose 的模型数值，跨平台等效性依赖 9.3 的适配记录。

| 角色 | 阻尼比 ζ | 刚度 k |
| --- | --- | --- |
| fast spatial | 0.6 | 800 |
| default spatial | 0.8 | 380 |
| slow spatial | 0.8 | 200 |
| fast effects | 1.0 | 3800 |
| default effects | 1.0 | 1600 |
| slow effects | 1.0 | 800 |

〔Vela 适配要求〕采用质量 m 的二阶模型时，须明确 `c = 2ζ√(km)` 以及秒、位置和速度单位；不能把表中的 ζ 直接代入速度阻尼系数。静止开始的初始速度为零，手势结束和动画改向使用当前速度。目标尺寸、行高等有内容约束的属性必须先满足合法范围；弹簧不能使点击盒缩到最小触摸目标以下。

每种属性登记可见误差对应的收敛阈值和速度阈值，不共用一个适用于像素、颜色和角度的任意 epsilon。超过运行边界时安全落到目标并清理回调；这属于本地保护策略，不是修改官方 token。参考曲线与弹簧参数分开记录，不能用同名角色掩盖两种实现的差异。

### 9.6 动效记录模板与所有权〔Vela 约定〕

每条登记至少包含：`motion_id`、触发状态版本、执行者、目标对象/属性、起点/终点/速度、scheme/token、实现类型、取消/重定向、减弱动态、隐藏/销毁清理和验收路径。实现类型明确写为弹簧、官方曲线近似或本地替代。

同一属性在同一时刻只有一个动效控制者。Shell 的根容器过渡与应用内容更新分用不同节点，不能同时写根节点透明度或位置。关闭即使没有过渡，也必须同步处理输入阻挡和焦点；视觉回调不能持有业务任务的唯一完成通知。

## 10. State、Input 与 Accessibility

主来源：S7。硬件按键、焦点栈和目标尺寸为本地约束。

控件必须分别处理 enabled、pressed、focused、selected/checked、disabled、busy，以及适用的 error 状态。不是每个控件都拥有全部状态；有状态的控件必须采用共享表达。焦点与选择含义不同，不能混用。

触摸目标原则上至少 48×48dp；相邻目标不得重叠。视觉上较小的图标通过容器扩展目标，而非扩大透明区域侵占其他按钮。桌面密度不能成为缩小主要操作目标的理由。

必须处理按下、移动、释放、取消、滚动接管和长按。开始滚动后不得在释放时误触卡片；长按后不得再触发点击。关闭或销毁页面时释放 pointer capture、定时器、回调与焦点引用，避免返回闪退和不可点击的透明层。

模态内容明确阻挡背景输入；非模态内容不得留下全屏透明拦截层。焦点移动、硬件操作与触摸结果一致，关闭浮层后回到合理的原焦点。

组件提供名称、角色、值和状态等可访问语义；平台尚未支持的读屏通道须列为能力缺口，不能仅凭语义字段就宣称读屏可用。文字放大后仍能完成核心任务，错误与成功不能仅靠颜色、声音或动画表达。

### 10.1 输入与状态优先级〔Vela 约定〕

disabled 阻止提交，busy 只阻止冲突的重复动作，selected / checked 表示值，focused 表示当前操作目标；这些状态可组合，不能共用一个布尔字段。按键 Enter / Space 与触摸必须走同一业务动作，并防止按下、抬起各执行一次。硬件长按成立后吞掉对应短按。

焦点顺序遵循阅读顺序，不能落到已隐藏、禁用或被模态层覆盖的对象。滚动区须能把聚焦项带入可见范围，焦点框不被圆角或父容器裁掉。重要提示改变可访问状态，但不能无条件抢走正在编辑的焦点。

### 10.2 状态表达与手势仲裁〔Vela 约定〕

选择值、交互状态和异步请求阶段分别建模。selected 可以与 focused、pressed 并存；错误说明也可能与可重试按钮并存。视觉状态层只选一个当前交互层，不把 hover、focus、press 的透明度相加。具体颜色、透明度和形变按该组件固定版本的 token 登记，不为所有控件套同一组数值。

按下先提供本地反馈；移动超过滚动判定后，把本次序列交给滚动，释放不能再执行点击。手势归属交接时发出取消并清理按压态；多指、离开边界、页面切换和设备失焦不能留下悬挂长按。触摸、键盘与硬件按键最终调用同一动作入口，入口校验目标版本、可执行状态及重复请求。

焦点不是触摸悬停的副作用。列表重排按稳定对象恢复焦点；原对象消失时选择相邻合理目标或父级入口。模态层关闭后恢复到仍有效的触发控件；用户主动滚动时，不得由周期刷新不断把视口拉回旧焦点。

## 11. Components：组件与交互规范

主来源：S8–S10；统一组件目录为 Vela 约定。

| 类别 | 本地使用规则 | 必查状态/行为 |
| --- | --- | --- |
| Button / Icon button | 主次操作有层级；同组文字与图标共用度量 | pressed、disabled、busy、焦点、重复提交 |
| Button group / Chip | 相关选择紧密分组；选择与执行动作分开 | 单选/多选语义、选中反馈与禁用原因 |
| Switch | 直接表达可切换状态 | 待提交、确认成功、失败回退；不伪装立即成功 |
| Slider | 显示当前值及边界，拖动预览与最终提交区分 | 取消、连续事件、提交节流与失败 |
| List / Menu | 内容、说明与尾部操作位置稳定 | 长标题、滚动、选中、关闭与焦点恢复 |
| Card | 摘要、主入口与次操作分明 | 整卡点击与内部按钮无手势冲突 |
| App bar | 标题、返回与必要操作稳定 | 窄屏、长标题、系统浮层覆盖 |
| Text field | 标签、值、提示与错误区分 | 中文、选择、键盘遮挡、提交与取消 |
| Dialog | 应用内管理；明确标题、内容、动作 | 焦点约束、返回/遮罩策略、危险动作确认 |
| Snackbar / 临时反馈 | 用于短暂结果与可撤销操作 | 不遮挡关键操作；重要失败保留可追溯入口 |
| Progress / Loading | 有真实比例才用确定进度 | 无比例使用不确定反馈，明确等待阶段与失败出口 |
| Calendar | 时间范围、来源与全天/定时语义明确 | 多日历、重复实例、跨日、时区与空状态 |

“忙碌”不等于所有按钮禁用。只限制会冲突的操作，保留返回、取消或查看状态等安全路径。危险操作针对稳定对象标识确认，不能依赖提交时可能已变化的列表位置。

日历以实例表达重复事件，不能把同一系列的所有实例去重成一条。日历筛选、同步覆盖范围、最近同步结果分别显示；没有数据时区分无日程、范围外、加载中和同步失败。UI 规范不代替端到端同步完整性验证。

### 11.1 组件说明的统一格式〔Vela 约定〕

每种组件的实现说明须包含用途与禁用场景、变体、结构槽位、设计角色、尺寸约束、输入事件、可访问语义、异步/错误行为及生命周期。扩展组件沿用这一格式，不另造一套命名和状态机。仅存在一个绘制函数或一张静态截图，不算组件契约完成。

按钮至少区分突出操作、次要操作和低强调操作；整张卡片不能默认绘成主要按钮。选择控件区分单选、多选和立即开关，导航目的地不能伪装成可切换开关。菜单承载临时动作或选项，不能替代整个应用的页面架构。Snackbar 不能承担必须确认、持续跟踪或不可丢失的任务结果。

### 11.2 Modal、菜单与输入法〔Vela 约定〕

Dialog 由当前应用管理，焦点限制在自身；返回默认关闭当前可取消交互，确认动作验证稳定目标。点击遮罩是否可关闭由组件契约确定，不能把所有浮层一律设置为可取消。未保存编辑和破坏性操作须有明确处理。

菜单关闭后恢复到触发控件；输入法按当前输入焦点避让内容与提交区。返回先交给当前最上层可处理对象，一次只消费一层。仅关闭输入法不应同时退出应用。销毁局部交互须移除其遮罩、回调、订阅和焦点引用。

### 11.3 组件目录与适用边界〔Vela 约定〕

本表补足共享组件的分类范围。列入目录不等于必须立即实现全部官方组件；使用前必须有符合 11.1 的契约。尚未使用的组件记为未选用，不能写成已适配。

| 类别 | 必须区分的变体或用途 | 本地组合边界 |
| --- | --- | --- |
| Buttons | 执行动作与 toggle 选择；elevated / filled / tonal / outlined / text | 主操作稀少且明确；toggle 不采用 text 配置；同组遵循一致尺寸 |
| Icon buttons / FAB | 普通与选择态；标准图标动作与突出的主要动作 | 只有高优先级动作才使用 FAB；不以无标签小图标替代所有操作 |
| Button groups / Chips | 关联操作组；assist / filter / input / suggestion 等适用角色 | 输入 Chip 表示已有输入，filter 表示筛选值，不混用为页面导航 |
| Checkbox / Radio / Switch | 多选及部分选中；互斥单选；立即切换设置 | 依选择语义决定控件，不能只因外观类似而互换 |
| Slider | 连续/离散、单值/范围（实际使用时登记） | 显示单位和边界；范围端点有各自名称与可操作目标 |
| Text fields / Search | 输入、只读、密码（若支持）；查询与结果 | 输入保留草稿；搜索区分未查询、无结果、失败，不用同一空白页 |
| Lists / Dividers | 单项/多行、选择/动作、分组边界 | 行内主要动作与尾部动作目标分开，分隔线不成为焦点 |
| Cards | filled / elevated / outlined | 容器可不交互；交互卡片说明整卡动作与内部动作 |
| App bars / Toolbars | 页面导航、上下文操作 | 放在宿主分配区域；宽度不足时保留返回和核心操作 |
| Navigation bar / Rail / Drawer / Tabs | 应用目的地、可变宽度导航、同级内容页 | 由信息结构选择；Tabs 不代替桌面磁贴吸附和全局分页 |
| Menus / Tooltips | 临时动作与选项；辅助解释 | Tooltip 不承载唯一必要说明，触屏用户也能获取动作含义 |
| Dialogs / Sheets | 局部确认、编辑或补充内容；modal 与 non-modal | 应用局部 Sheet 与 systemOverlay 是不同所有权，不按滑入方向判断 |
| Snackbar / Badges | 短反馈及撤销；计数/提醒标记 | Badge 不承载长正文，不把不可丢失失败只放进短暂反馈 |
| Progress / Loading | 真实比例与不确定等待；局部与任务级反馈 | 不把 loading 形变当作任务进度，不在所有卡片无限播放 |
| Date / Time pickers | 日期、时间和范围（实际支持时登记） | 与日程列表区分；校验时区、全天和起止关系 |
| Carousel / 内容滑动容器 | 有边界的同类媒体浏览（若选用） | 不替代 Shell 桌面网格，不引入第二套全局分页 |

### 11.4 按钮的 Expressive 变体与测量

S8 的 Buttons 发布快照区分 default 与 toggle 两类行为、五种颜色配置、XS / S / M / L / XL 五种尺寸及 round / square 形状。它们是组合维度，不能把“五种颜色”误写成五种业务动作。尺寸数值应按选定组件 token 登记，正文没有提取到的测量不凭图片估算。

图标视觉尺寸按组件角色确定：普通独立图标常用 24dp；该版本文字按钮的前导图标推荐 20dp。两者均不改变至少 48dp 的交互目标要求。小号按钮可采用更小的视觉容器，但必须在布局中分配不重叠的触摸盒。

〔Vela 约定〕默认文字按钮采用 Label large；更大尺寸若选用，需登记对应文字角色和间距。按压形变、toggle 选择形变和主题圆角分开映射，不能给所有按钮永久设置 full 后宣称实现 Expressive。按钮文字、图标和 loading 占位共享测量，busy 时不使相邻控件横跳。缺少所需字形、资源或可执行动作时有明确降级，不能留下可点击空白按钮。

### 11.5 组件登记及审核记录〔Vela 约定〕

每个实际使用的组件记录：稳定组件 ID、官方来源/快照、选用维度、槽位、Color/Typography/Shape/Motion 角色、视觉尺寸与触摸盒、字体放大重排、交互状态、可访问语义、数据/错误契约、宿主所有权、清理行为和证据。派生组合引用基础组件记录，再补差异；不能复制数值后失去来源关系。

审核一条组件记录必须同时覆盖默认、按下、焦点、禁用及适用的选择/busy/error 状态，并至少有长文字、资源失败和窄/矮区域路径。不存在的状态标为不适用并解释，不能用空格当作通过。组件审核结论不能自动覆盖所有页面的组合与实际数据行为。

## 12. Desktop：磁贴组织、方向与吸附

以下为 Vela 产品约定；视觉继续遵守 S3、S5、S8。

### 12.1 组织与内容

采用类似 Win8 的磁贴组织方式：**横屏沿水平方向组织和滚动，竖屏沿垂直方向组织和滚动**。横屏允许较高的卡片并排，也允许同一网格中的大小磁贴组合；不是把每张卡片拉成同样比例。

磁贴类型区分应用入口、长期 Widget 和进行中的 Live Activity。长期时钟、日历概览是 Widget；有明确生命周期的倒计时、专注、做饭任务可以是 Live Activity。类型不能仅由外观判断。

Shell 根据可用区域、间距及内容约束分配统一网格。尺寸等级描述网格占用与内容优先级，不让应用声明固定屏幕坐标。不使用全局“1/2、2/2”分页器作为桌面结构，也不要求一个视口只能放一张卡片。

每张卡片有清晰标题、关键内容和稳定操作入口。减少多层描边、重复标题、大量空药丸与装饰性状态字。不要把后台诊断信息默认铺在桌面。

### 12.2 滚动与停止吸附

- Shell 维护卡片/分组的合法吸附锚点。手势结束后，根据当前位置、速度和边界落到合适锚点；低速拖动偏向邻近位置，快速滑动可以跨过多项。
- 停止时主要卡片或分组应完整、对齐地呈现，避免只剩无法理解的半张主内容。吸附不等于强制一屏一卡。
- 超出视口的长正文进入应用详情阅读；不得靠桌面磁贴内部无限嵌套同方向滚动解决。
- 内部可交互控件与桌面滚动有明确手势仲裁。应用内容不继承“任意横滑都切桌面”的全局手势。
- 插入新数据、任务状态变化、主题切换后保留当前稳定内容锚点，不能自动跳到第一张。旋转时按内容标识映射新位置。
- 滚动和吸附过程中不重复创建卡片、读取字体或重新栅格化整套图标。焦点和触摸目标以实际显示位置为准。

## 13. App、System Overlay 与详情体验

以下为 Vela 产品约定；组件依据 S8、S9。

### 13.1 应用打开态

应用打开后形成完整工作区域，标题/导航、内容和必要操作区清晰。Shell 根据约束选择可用的单栏或多栏呈现；应用不自己决定从屏幕哪里弹出，不隐藏桌面控件来拼出另一套全屏管理。

应用可在内部组织列表、详情与编辑。宽度足够时可以列表/详情并排，否则按内部路由切换。切换形式不改变对象标识、草稿与操作结果。

### 13.2 控制中心

控制中心声明为 `systemOverlay`。Shell 决定打开边缘、区域与遮罩；内容自身只负责在给定区域内布局。

〔Vela 约定，按用户要求更新〕顶栏采用紧凑的系统状态栏，显示时间及真实连接状态，不放置控制中心按钮或应用操作。助手等应用入口归入桌面。状态栏常态保留在应用上方，由 Shell 统一预留区域；系统浮层可覆盖状态栏。默认高度以 24dp 为起点，文字放大时按实际行高增高，不以裁字维持固定像素高度。

从状态栏开始向下拖动打开控制中心；页面内容区的普通滚动不能触发。指针轻点、短拖、横滑和反向拖动不打开；识别后消费本次接触的剩余事件，松手不得误触已出现的开关。当前本地识别基线为向下至少 32dp 且垂直位移占优，属于产品参数。键盘/旋钮可聚焦状态区域并激活同一入口；触摸下拉不抢走当前应用的编辑焦点。控制中心入场采用顶部方向，关闭后恢复原宿主与有效焦点。

标题与关闭入口固定。常用开关、模式选择和状态说明分别分组。关联模式优先使用紧凑的单选组，不把所有项目做成整屏长按钮。开关用开关语义；操作提交后在原处反馈，避免立刻关闭让用户无法确认。

对真实设备状态存在异步确认时，显示待生效与失败原因；不能把 UI 已选中当作模式已切换。滚动列表不带走唯一关闭入口，关闭后移除遮罩及输入拦截。

### 13.3 助手、历史与记录详情

助手文字使用完整中文字体链。输入、当前请求状态与结果阅读区域分离；“历史”等按钮与同层操作统一文字角色和对齐。

记录详情采用可持续阅读的页面结构。标题、返回和主要动作保持可达，正文单独滚动。流式内容到达时，只有用户已在末尾且允许跟随才继续跟随；用户向上阅读后以“有新内容”入口提示，不能强制拉到底部。

保存、识别、执行、同步分别显示真实阶段。请求入队后可回到桌面，但应保留可追踪状态；不能在仅入队时显示“已完成”。失败应有明确重试或查看原因的入口，而非永久停留在泛化的“处理中”。

## 14. Notification、Live Activity 与 Widget

主来源：S11。统一构造与桌面投影是 Vela 约定，不是 Android 官方桌面能力声明。

### 14.1 统一构造

应用提交结构化描述，由系统组件构造外观。公共语义至少包括稳定 key、来源应用、频道/类别、标题、内容、样式、重要性、时间、动作和目标路由；按需包含 ongoing、到期策略、进度和隐私级别。

采用统一的基础、长文本、进度等样式以及标准动作结构，不让应用提交任意绝对布局代替通知。动作携带稳定对象/任务标识，处理重复触发与失效状态。私密内容在桌面展示前遵守可见性设置，不默认公开完整文本。

### 14.2 进行中的活动

Live Activity 用于需要持续关注、有明确任务状态的活动。借鉴 Android 对用户相关、时效性任务的选择原则；不能把所有后台请求都变成常驻活动。

同一任务的通知、桌面卡片和应用详情来自同一状态源与任务标识。桌面可展示摘要、进度与少量关键动作；Shell 决定尺寸和位置。用户移除桌面展示不等于取消任务，取消必须有明确动作和反馈。

倒计时至少区分运行、暂停、完成、取消和恢复失败等适用状态。运行中的剩余时间依单调时间计算，日期与日程依正确时区和墙上时间显示；校时不能把正在运行的倒计时随意拉长或缩短。重启恢复须单独验证，无法确定时明确说明，不能制造准确倒计时。

长期 Widget 与 Live Activity 使用共同视觉角色，但生命周期不同。计时完成后通知结果并退出进行中状态，不无限保留“正在运行”的旧卡片。

## 15. A2UI、自动菜谱与生成界面

以下为 Vela 产品约定；组件视觉遵守 S3–S10。

生成界面使用共享组件目录与语义角色，接受宿主约束。不得由生成内容注入全局打开坐标、覆盖 Shell 导航、创建全局 Dialog 或执行未声明动作。需验证组件类型、文字长度、稳定 key、动作参数与资源预算；失败时提供可读的降级界面。

自动菜谱属于应用内容：概览、材料、当前步骤、步骤详情与任务操作分层。窄屏优先当前步骤，宽屏可将材料或步骤导航并排。只有实际支持并确认的动作才显示为可执行。

步骤切换保留任务状态；计时器由用户明确开始，绑定步骤和稳定任务标识，避免返回或重绘时重复创建。离开菜谱后，已开始的做饭计时可通过 Live Activity 延续。步骤完成与计时完成不能混为一谈。

现有固定纵向模板或协议项数上限是实现现状，不是 M3E 的设计限制。本文不代表自动菜谱、所有生成页面或桌面投影已经完成改造。

## 16. Feedback、Writing 与系统状态

主来源：S7、S9、S10；以下文案映射为 Vela 约定。

文案直接说明当前阶段、结果与下一步，使用统一动作动词。不得把内部线程、协调器或传输术语默认暴露给用户，除非有助于用户处理问题。

| 情况 | 应表达的内容 | 不合格表达 |
| --- | --- | --- |
| 录音准备 | 当前是否已能采音；未就绪时说明准备中 | 按下立即假装开始录音 |
| 识别与执行 | 分清识别中、执行中、执行结果 | 所有阶段永久显示“处理中” |
| 恢复状态 | 恢复对象、失败与可继续路径 | 无限停留“历史状态恢复中” |
| 网络/配置错误 | 用户可理解的原因与重试/设置入口 | 一律“服务暂不可用”或伪造成功 |
| 空内容 | 没有内容的范围与建立内容的入口 | 与加载失败共用同一空白页 |
| 删除/取消 | 明确目标与后果，必要时确认 | 模糊“确定”导致不知取消哪个任务 |

耗时阶段必须有可观察的开始、完成与失败边界。无真实进度时不显示虚构百分比；内容没有变化不意味着应该播放无限动画。具体超时与性能预算由相应业务链路定义并测量，不能从动画时长倒推。

### 16.1 本地化与时间表达〔Vela 约定〕

动作命名、标题大小写、标点、单位和错误语气须集中一致。布局允许翻译后文字变长，不把中文两个字的宽度当作通用按钮宽度。文字方向变化时，阅读顺序、图标方向与焦点顺序一起核对。

日期、星期、12/24 小时制与时区按设备/用户设置表达；相对日期应能追溯到明确日期。计时长度与日历时间分别格式化，不把“30 秒”渲染成一个日期。未校时、离线缓存与同步失败必须如实表达，不展示看似准确的错误时间。

### 16.2 图像、图表、声音与触觉〔Vela 约定〕

图像与插画须有来源和授权，区分信息图像与装饰图像。照片、封面和头像可以采用适用裁切，包含文字、菜谱材料或其他重要信息的图片不得盲目裁切。加载中、失败和缺失状态须有稳定占位，不能挤走当前操作。图像不替代 Material Symbols 操作图标。

图表、活动进度和时间线须标明单位、范围及对应文字值；不能只靠颜色区分系列。没有真实数据时显示缺失或等待，不用装饰性随机曲线制造观察结果。

声音与触觉仅作为视觉反馈的补充，遵守静音、勿扰及设备能力；没有对应硬件时不显示虚假的可用设置。录音开始/结束、计时完成等反馈不得与实际业务状态错位。声音、振动、动画完成都不是任务成功的依据；听觉或触觉关闭后核心操作仍可完成。

## 17. Rendering、性能与资源约束

以下为 Vela 实现要求，不属于 Material 官方性能参数。

- UI 线程不得承担阻塞网络、模型调用、大文件写入、全盘扫描或重复字体加载。准备、识别、执行和可选录音归档须有清晰的异步状态；即时命令不因无业务必要的归档阻塞结果展示。
- 字体与图标按需加载并缓存，失效与回退有边界。不能每帧读取文件、生成位图或重新构造整棵控件树。
- 仅重绘变化区域。倒计时只更新所需内容，不能每秒重绘整个桌面；持续动画须有可见性和功耗策略。
- 页面关闭后取消其展示订阅和定时回调，业务任务独立管理；防止悬空对象、重复订阅和退出后仍刷新。
- 绘制边界、stride、像素格式、缓冲区生命周期和硬件加速访问范围必须正确。dp 改造不能改变这些像素/字节安全约束。
- 资源不足时减少装饰、缓存或并发内容，不通过取消必要触摸反馈、缺失中文、丢弃任务结果来换取表面流畅。
- 性能验收分别记录输入反馈、内容呈现、业务完成与主线程阻塞。动画帧率不能代替业务延迟，也不能用外部 API 耗时解释本地准备或保存的全部延迟。

## 18. 一致性审核与验收

### 18.1 覆盖清单

| 范围 | 最少覆盖内容 | 通过依据 |
| --- | --- | --- |
| Layout | 当前 S1、另一比例、横竖屏、窄/矮区域、字体放大 | 无裁切关键内容，触摸可用，重排保留状态 |
| Typography / Glyph | 中文混排、长标题、数字、标点、缺字、字体失败、所有动态宿主 | 无方框与乱码，回退可定位，角色和基线一致 |
| Icons | 全部图标来源、不同 DPI、选中与禁用 | Rounded 家族一致，目标像素清晰，触摸盒正确 |
| Color / Shape | 主题、实际叠加背景、层级、对比度、圆角裁剪 | 语义角色一致，关键状态无需只靠颜色理解 |
| Motion | 打开、关闭、返回、吸附、打断、减弱动态 | 连续可控，不阻塞输入，不伪造业务成功 |
| Navigation | App、系统浮层、局部 Dialog、菜单、键盘、Home 长短按 | 单次动作只处理应处理的一层，焦点恢复 |
| Components | 每类控件及其适用状态，长文本与 busy/error | 共用规则，无透明拦截层、误触和重复提交 |
| Desktop | 混合尺寸卡片、边界吸附、快速滑动、插入/删除、旋转 | 方向正确，落点合法，内容锚点稳定 |
| Tasks | 倒计时、通知、Live Activity、多展示面与恢复 | 同一任务一致，关闭展示不取消任务 |
| Content | 助手、记录、日历多来源/重复实例、控制中心、菜谱/A2UI | 业务语义正确，各内容区遵守共同宿主规则 |
| Lifecycle / Performance | 反复进退、切换、长文本、资源压力、任务并行 | 无失去响应、泄漏式增长与过期回调 |

实际尺寸、逻辑 DPI、字体缩放、系统版本与观察结果须记录。静态代码审查、离屏渲染、模拟器、真机交互和人工可读性评估分别标注；缺少其中必要证据时记为待验证，不能合并写成“全部通过”。

### 18.2 当前已知迁移差距

以下记录规范制定时的基线差距；后续实施状态以代码和验收证据为准，不作为当前代码仍有同一缺陷的断言：

1. 全局导航与应用自身的打开、浮层逻辑仍需收敛到 Shell；旧分页和各页独立定位需要按新规则迁移。
2. 字体继承存在明确风险：Tileview 的主题样式可能覆盖根字体；A2UI 的按钮、关闭及动态标签未全部显式采用共享字体角色。需要覆盖所有宿主与控件，不能只修助手正文。
3. 字体角色、图标原生尺寸与 dp 映射已有部分基础，不能据此认定全部页面完成 M3E。需按新角色和矩阵逐一核对。
4. 控制中心、卡片展开与记录详情需要统一固定导航、内容滚动和操作区域；返回与关闭必须核对对象生命周期及输入层清理。
5. 磁贴网格、横竖向滚动吸附、统一通知与桌面 Live Activity 是目标结构，须以实际代码和设备证据验收。
6. 日程同步完整性、录音链路耗时等仍属业务与性能问题。新外观不能替代问题修复，也不得掩盖失败状态。

### 18.3 完成定义

一项 UI 改造只有同时满足相关视觉角色、布局约束、交互状态、生命周期和实际数据语义，才可以标为完成。若仍有字体方框、无法点击、返回失效或状态虚报，即使截图符合视觉设计也不得通过。

后续改造应按完整用户链路交付，并在同一条目记录涉及的组件、页面与验证证据。本文作为统一约束，不再为每个局部问题另建一套导航或样式规则。

### 18.4 页面与共同规则的对应〔Vela 约定〕

下表是最低审核范围；新增页面、Dialog、菜单或生成组件须加入相应范围，不能以“非主页面”为由跳过共同规范。

| 页面或展示面 | 内容与导航要求 | 专项审核 |
| --- | --- | --- |
| 桌面 / 磁贴展开 | 网格与摘要由 Shell 组织；展开进入稳定对象的详情 | 横竖方向、混合尺寸、吸附、内容锚点、内部按钮手势 |
| 助手 / 录音 | 全局入口与结果阅读分离；请求状态可追踪 | 字体方框、按压反馈、准备/采音/识别/执行、返回与持续任务 |
| 历史 / 记录详情 | 固定导航、正文滚动、明确来源 | 同组文字对齐、增量更新、阅读位置、对象失效 |
| 待办 | 列表/详情/编辑遵守应用内部路由 | 稳定 ID、完成与撤销、长标题、空/错状态 |
| 日历 / 日程详情 | 多来源、范围、实例与时间语义明确 | weekly / daily 等重复、全天、跨日、时区、同步覆盖与失败 |
| 控制中心 / 设置 | systemOverlay 宿主，分组操作与固定关闭 | 开关真实确认、单选模式、长列表、遮罩与焦点清理 |
| 通知中心 / Live Activity | 同一结构化状态、多展示面、明确动作 | 隐私、去重、过期、关闭展示与取消任务分离 |
| 菜谱 / A2UI | 概览、材料、当前步骤与任务操作分层 | 约束校验、窄宽屏、计时显式开始、步骤完成独立、失效动作 |
| 配网 / 首次使用 / 成员与连接状态 | 引导步骤可解释、可返回，状态来自真实设备 | 等待/错误/重试、中文输入、连接变化、重进与恢复 |
| 共享 Dialog / 菜单 / 输入区 | 应用内所有权，公共组件与焦点规则 | 48dp、字体放大、键盘避让、取消、重复按键、资源失败 |

验收记录至少包含：条款/页面、代码位置、设备或宿主环境、像素尺寸/逻辑 DPI/字体缩放、使用数据、操作路径、预期与实际、证据位置，以及未覆盖项。实现状态分为未实现、部分实现、已实现待验证、已验证；截图或主机测试不能自动升级成真机已验证。
