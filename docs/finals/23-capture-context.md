# 捕获时的粗粒度地点与日程上下文

2026-10-23。此项只实施与静态回顾，未运行测试、构建、模拟器或设备。

## 用户流程

Android 设置 → 捕获上下文，分别启用粗略位置、当时日程和设备共享。默认均关闭。位置只申请前台 coarse 权限；日程只申请读取权限。录音、Widget、通知与文字入口仍先保存原始内容，权限拒绝、系统服务失败、没有位置缓存不阻塞保存。

卡片详情可展开捕获上下文，查看源设备、捕获和采集时间、位置区域、位置观测时间与当时日程。没有数据时区分未启用、未授权、没有近期位置、系统服务不可用、读取失败、过期、设置改变和来源设备未提供。不会把手机导入时的地点或日程冒充 Vela 捕获时的上下文。

## 采集与持久化

- `CaptureCreated`、`CaptureContextRequested` 与 pending job 一同提交。后台 worker 在提交后读取系统服务，追加一次不可变 `CaptureContextCaptured`，并在同一事务删除 pending job。读系统服务时不持有数据库事务，也不改写原始事件。
- job 使用持久 request event ID，完成时核对当前请求与已有结果。数据库写入失败保留请求供重启恢复；超过捕获后一分钟的任务只记录过期，不读取当前状态补历史。独立 pending 表避免每秒扫描全部历史事件。数据库版本 21 为新建及旧库升级建立该表和查询索引。
- 本机采集资格由本机入口显式设置，不能由上传报文的 `device_id=android` 冒充。文本、正常录音、待重试音频均保留捕获时的策略；录音恢复元数据保存本机资格和权限快照，恢复不套用后来新授予的权限。旧恢复文件默认不创建本机采集。
- 位置仅使用捕获前十五分钟内的 network-provider 缓存，保存纬度 0.1 度的区域，并按纬度扩大经度格宽；不保存精确点、地址、GPS 轨迹或高度。数据保留缓存观测时间，不把旧 fix 说成实时定位。
- 日程查询捕获时刻正在进行、非全天且未取消的 occurrence，保存最多三项标题和 begin/end，另记是否还有重叠事项。标题有界，不读取说明、参会人或外部链接。query 使用取消信号和 1.5 秒取消期限；provider 是否及时响应取消仍属运行边界。
- 关闭采集或撤销权限时，未完成 job 取消或去掉刚读取的内容。仅改变共享开关不取消原有本机采集。关闭设置不删除先前合法保存的历史快照。

## 复制与隐私

本机历史默认留在本机。用户额外开启设备共享后，卡片 CRDT 携带有界 `capture_context` 和显示摘要，复用现有已认证、加密的 Fabric 应用通道。每次分片发送前再核对当前权限与共享策略；失效时丢弃旧发送快照、重新生成脱敏版本。已进入底层传输队列或已送达的字节无法撤回。下一次成功同步将撤下对端当前展示内容，不宣称可清除对端历史。

旧明文 LAN `cards.get` 路径不携带上下文。Android 不继续转发别的设备提供的上下文；收到的共享快照须通过严格字段、大小、状态、时间、区域及日程边界校验，并保存 `CaptureContextImported`/撤销事件。原始源事件的身份与因果链复制仍由任务 05 负责；本项复用既有卡片载体共享快照，不把它宣称为完整事件复制。

删除卡片的 CRDT 墓碑也显式清空上下文寄存器，避免旧私密值随删除消息继续传输，或在权限复查时让删除消息无法前进。

Vela 卡片详情可显示授权摘要；其 `search_records` / `read_record` 输出显式移除上下文，追问使用独立的无上下文详情函数。Android 的分类工具同样仅发送原有卡片字段，均不会因开启设备共享而自动把采集上下文提交云端模型。

## 静态回顾证据

- 源仓库与参赛快照对照：原 Capture 模型相同、均无上下文字段；现行 Android 集成与 manifest 已存在项目差异，此项落在参赛应用，不覆盖独立框架仓库。
- `CaptureContext.kt`：版本、来源、时间、可用/不可用状态、8 KiB 预算、位置及最多三项日程校验和用户说明。
- `BufferCaptureContextWorker.kt`：提交后采集、窗口判断、位置量化、query 取消、失败状态。
- `BufferRepository.kt`：Capture 入口、恢复文件、事件与 queue 原子提交、幂等完成、旧库升级、详情读取、授权投影与导入。
- `BufferCaptureContextPanel.kt`、`BufferScreen.kt`、`BufferCardDetailContent.kt`：设置/系统权限/关闭及详情入口。
- `VelaCardReplicaProtocol.kt`、`VelaFabricEnrollment.kt`：已排队快照逐分片授权复查与正式通道；`BufferWire.kt` 使用默认不含上下文的序列化。
- `buffer_replica.c/.h`、`buffer_followup.c`：本机显示与模型工具/追问内容的边界。

复核覆盖拒绝权限、权限中途撤销、关闭后重开、分享开关变化、音频保存故障恢复、源设备伪装、旧数据、重复完成、超时、断连重试与原始事件不可变性。真实权限/provider/后台/蓝牙行为尚未验收。
