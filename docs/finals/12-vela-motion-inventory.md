# Vela 全页面与全交互动效清单

日期：2026-10-19。接续 [界面整体审查](11-vela-m3-expressive-review.md)。范围覆盖当前 Vela 自有 UI 的所有页面类型、模式和公共组件，以及它们的正常、进行中、成功、失败、中断与退出状态。**这是调研与目标行为清单；未实现动效、未启动模拟器。**

## 1. 官方基线与“全覆盖”的含义

本清单依据 [M3 Motion physics](https://m3.material.io/styles/motion/overview/how-it-works)、[Motion specs](https://m3.material.io/styles/motion/overview/specs)、[Interaction states](https://m3.material.io/foundations/interaction/states)、[Gestures](https://m3.material.io/foundations/interaction/gestures)，以及 [Usability](https://m3.material.io/foundations/usability)、[Loading indicator](https://m3.material.io/components/loading-indicator)、[Progress indicators](https://m3.material.io/components/progress-indicators)。官方正文读取方式及版本见上一报告。

“全覆盖”意味着每项有明确动效或静止策略，也包含输入命中、焦点、取消和恢复。以下标签统一用于清单：

| 标记 | 含义与适用对象 |
|---|---|
| SF | fast spatial：按钮尺寸/圆角、局部交互形状 |
| SD | default spatial：局部面板展开收起及中等范围的空间关系 |
| SL | slow spatial：确有需要的整页/大范围空间转换 |
| EF | fast effects：按下、选中、可用性等颜色/透明度反馈 |
| ED | default effects：内容、提示与状态交接 |
| LIVE | 随真实手势、时间或任务进度变化；不虚构业务进度 |
| STATIC | 保持稳定，避免干扰或误导 |

它们是官方 motion 角色的设备侧映射建议，不是已经接入的代码 token。尺寸、位置、形状使用 spatial；颜色、透明度使用 effects，不能越界回弹。速度取决于影响范围及设备情境，不机械套用一个时长。LVGL 上需验证映射；官方 Web spring-to-curve 表不能直接视作 Vela 的强制参数。

## 2. 当前实现覆盖与缺口

| 页面/组件族 | 当前可确认的实现 | 动效结论 |
|---|---|---|
| 首页日常、专注、睡前、深挖 | 共用首页；专注切换为独立计时 panel，其余保留卡片结构 | 未发现统一页面/模式转换 |
| OOBE 六类页面 | WELCOME、VERIFY、NETWORK、SERVICE、READY、BLOCKED；另有 busy/retry hint | 主要直接改文字与显隐，未发现阶段转换体系 |
| 录音 | 按下开始、松开或 PRESS_LOST 保存；背景变红、文字更新时间 | 有直接状态反馈，尚无统一形状/取消动效契约 |
| 卡片、翻页、动作行 | 相同对象替换内容，按卡片支持的动作显隐按钮 | 未发现方向性翻页和局部完成转换 |
| 专注圆环 | 每次刷新按真实 remaining 直接更新 arc value | 有数据变化，不能等同 spring motion |
| 助手 timer/alarm | 默认 inline surface；动态标签反映 domain 状态 | 缺少一致的展开、收起和动作状态转换 |
| 问答、翻译、菜谱 | 默认 full-screen surface，保留底部录音入口 | 主要显隐与重建，缺少进入/返回关系 |
| 通用 A2UI 组件 | Column、Row、Card、Text、Button、Divider 及四类定制组件 | 没有贯通各组件的统一 motion/state 映射 |

主要依据：[buffer_ui.c:682](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_ui.c:682)、[buffer_ui.c:583](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_ui.c:583)、[buffer_oobe_ui.h:9](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_oobe_ui.h:9)、[buffer_a2ui_internal.h:24](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_a2ui_internal.h:24)。

未发现项目显式配置的 `lv_anim` / spring / style transition 体系；这不排除 LVGL 默认主题及滚动物理存在自身效果，也不等于已经逐帧测过所有运行行为。

## 4. OOBE：六类页面及全部主要转换

| ID | 状态/转换 | 对象与动效 | 角色 | 必须保持的逻辑 |
|---|---|---|---|---|
| O01 | 第一次展示欢迎页 | 标题/说明一次入场；二维码稳定后显示 | ED，可少量 SD | QR 出现后保持静止，不逐点绘制、不形变 |

| O03 | 欢迎 → 核对数字 | 步骤与主内容交接，安全数字一次完整出现 | SD + ED | 不逐位滚动数字，不能让旧数字短暂可确认 |
| O04 | 确认数字一致 | 按钮即时反馈，再显示真实配对状态 | SF + EF，随后 ED | 未收到成功状态不提前展示“已连接” |
| O05 | 取消/拒绝/超时 | 返回可恢复的连接状态，提示原因 | SD + ED | 停止该次确认的动效和命中；允许重新开始 |

| O10 | SERVICE 配置中/验证中 | 当前任务明确；任务长短决定 loading/progress 形式 | LIVE | 不让短时花形 loader 无限代替长任务反馈 |
| O11 | 服务失败/重新验证 | 错误局部出现；验证开始后有可操作边界 | ED + EF | 错误可读且可恢复，不重播成功插图 |
| O12 | SERVICE → READY | 进入“已准备好”的品牌时刻；成功符号一次形成并稳定 | SF/SD + ED | 只表示服务/配置已就绪，不等于持久完成 OOBE |
| O13 | READY 空闲 | 成功图形、标题、主按钮静止 | STATIC | 不继续旋转，不保留半完成的假进度弧 |

| O15 | 完成标记持久化成功 → 首页 | 完成页向首页的明确一次交接 | SD/SL + ED | 必须真实完成后才开放首页与录音 |

| O17 | BLOCKED | 解释阻断及下一步；恢复后回到正确阶段 | ED，必要时 SD | 不把异常统统当“重新欢迎”或成功 |
| O18 | 步骤状态/重连恢复 | 更新必要的步骤标志和文案 | EF/ED | 同一阶段反复刷新不重播图形；重启从真实状态恢复 |

### 完成状态插图的具体处理

当前渐变 B + 双环来自 [buffer_oobe_ui.c:122](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_oobe_ui.c:122)，固定 74/61 弧长没有进度含义。它的整改应包括：

1. 验证过程中的活动反馈结束后，切换为有完成含义的形状/符号，不能在成功时继续像加载。
2. 允许一次品牌形状/符号建立过程；颜色交接不越界，二维码和安全数字不参与形变。
3. 完成符号、标题和 CTA 有清楚层级；就绪后全部稳定，不让符号持续呼吸、转圈。
4. 减弱动效时直接显示最终就绪形态；不是用更慢、更长的动画替代。
5. 动画不承担配对、配置或写盘授权。任何失败都能从当前画面进入真实的恢复状态。

图形本身与 motion 应同时整改；只替换静态图片仍不能形成完整 M3 Expressive 行为。

## 9. A2UI 渲染与动效的实现边界

| 组件/更新 | 需要定义的策略 |
|---|---|
| Column / Row | 空间分组及顺序变化；不默认给每个 child 加延迟入场 |
| Card | 容器出现、离开、内容高度改变；子控件一起保持裁剪与命中关系 |
| Text | 按真实变化更新；正文默认稳定，重要状态才局部 effects |
| Button | 接入 G01–G05，业务操作成功与视觉反馈分离 |
| Divider | 通常 STATIC；不单独做吸引注意的动画 |
| TimerCard / AlarmCard | 接入 A09–A17，使用真实 domain state |
| TranslationResult / RecipeStep | 接入 A04–A08，遵守阅读顺序与卡片范围 |
| create/update/delete surface | 在稳定 ID 上识别结构差异；删除先失去命中，再完成退出显示 |
| 相同 sequence / 重复快照 | 不改变画面，不重播动效 |
| 用户关闭后的迟到更新 | 不因 update 数据绑定自动复活已关闭页面 |
| 新任务切换旧任务 | 中断旧动效，旧 callback 不得修改新任务 |

当前 [buffer_a2ui_lvgl.c:401](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_a2ui_lvgl.c:401) 在结构/sequence 变化时会 clean 容器重建，并用 `LV_ANIM_OFF` 重置滚动。这个策略无法天然承载连续的组件级动效；不能只在 clean 前后套一个 fade 就宣称所有动效接通。

建议先以 surface/component 稳定 ID 做更新分类，区分内容变化、结构变化和任务切换；保护用户当前滚动。Agent 可以选择受控模板或语义状态，motion scheme、时长/物理参数、层级和安全边界由 renderer 统一控制，不让模型注入任意动画执行逻辑。

## 10. 工程、减弱动效与验收要求

### 工程规则

- 业务状态在 domain 提交；动画只是呈现。不能依赖动画完成回调创建记录、写完成标记、启动/停止计时或执行重试。
- 使用独立的帧更新机制。当前 UI 刷新周期为 500ms，见 [buffer_ui.c:1124](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_ui.c:1124)，不足以直接驱动平滑交互；不能靠缩短全量业务刷新来代替动画调度。
- 动画使用单调时钟推进；连续点击从当前视觉值与速度重定向，释放/销毁页面时取消旧动画与回调。
- 每个视觉属性有明确归属，避免 layout、scroll、spring 同时写同一位置；主线程不能用 sleep 等待动画。
- 持久时间与界面插值分开。闹钟和计时器恢复后从真实状态计算，不回放漏掉的每一秒。
- 先修可用宽度、字体、卡片范围、触摸区域和按下对比度，再做形变；动画不可遮掩不正确的布局。
- 性能预算以 Vela 目标设备实测确定；不承诺未测试的帧率。低性能时减少同时运动层和大面积透明混合。

### 减弱动效

关闭装饰性 spring、持续呼吸、旋转和大位移；保留可读状态、明确焦点及必要的任务活动表达。OOBE 就绪直接显示最终符号；翻页直接换到目标或简短交接；记录、错误和提醒仍必须清楚。保留真实进度与用户跟手操作，不把“减弱动效”做成失去反馈。

### 最低验收矩阵

| 维度 | 必须验证 |
|---|---|
| 正常路径 | O01–O18、H01–H16、R01–R11、C01–C12、A01–A20 与公共 G01–G13 |
| 密集输入 | 快速连点、按住时来提醒、滚动中收新卡、切换任务时迟到回执 |
| 业务失败 | 文件写入失败、配对拒绝、网络/服务超时、ASR 无声、状态冲突 |
| 生命周期 | 页面关闭/重开、设备恢复、断连重连、相同快照反复到达 |
| 屏幕/内容 | 320×480、240×320、中文长标题、超长译文、长菜谱、嵌套卡片 |
| 无障碍 | 减弱动效、状态对比度、焦点与命中、无声/无颜色线索时可理解 |
| 性能 | 记录输入不丢事件、计时不受动画拖慢、无持续高负载和明显掉帧 |
