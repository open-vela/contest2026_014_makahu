## 助手状态与原始请求

启用 `BUFFER_VELA_SOURCE_JOURNAL` 时，计时器、闹钟及操作检查点改由类型化 `assistant.json` 投影保存，与对应不可变事件、实体索引和源 head 走同一 pending 提交。关闭该配置仍使用原 `assistant.state` 二进制文件。

JSON 显式保存 timers、alarms、operations、next_sequence、operation_next 和本次 request，具有独立 schema_version。64 位序号、指纹和时间字段用十进制字符串保留精度，不依赖 C 结构体布局。加载核对字段类型、数量、容量、状态、边界、ID、重复身份及序号。旧二进制先核对原 CRC、结构及语义，再迁移为 legacy_local 的状态快照；不伪造旧操作的原始事件，旧文件保持原样。

源事件区分初始化、操作提交、到期、重启恢复、显示请求及显示失败。计时、闹钟请求保留参数和操作 ID；翻译、菜谱也保存本次输入内容，不能仅用不可逆指纹充当原始请求。历史 request 是数据，解码不会调用执行器或呈现界面。

已修复操作环形表第 32 条将 next 写成 32 的越界：新写入取模；旧文件只有在原 CRC 正确、记录数恰好为 32 时才接受这一已知旧表示并归零。序号接近 uint64 上限时拒绝新操作，避免回绕。

**尚未完成长期去重。** 当前执行器仍主要使用 32 条操作缓存；journal 保留旧事实不等于执行入口会检索全部历史。下一步必须添加与源提交同步的持久操作索引，并处理已有 journal 的回填、同 ID 异请求及显示失败后的重试，不能将该环形表称为永久幂等账本。

## 到期与写入失败

工作线程先暂存到期状态与通知队列，提交成功后才派发。失败恢复队列长度和原单调时钟期限，修复原来失败仍通知、下次轮询又通知的路径。初始化恢复失败同样撤回暂存通知。

WAL 已接受但调用返回错误时，不能在旧内存状态上继续执行下一条操作：保存入口先尝试恢复并比对已提交投影；仍不确定则置恢复标记。工作线程、执行入口及读取快照在继续前都先恢复。对仍运行的同一计时器保留原进程期限；无法可信恢复的新期限暂停，不重新开始完整时长。到期状态持久可读，但不承诺屏幕回调在任意断电点恰好送达一次。

## 专注提醒

`focus.conf` 的间隔读写接入同一 journal。新增 `focus_runtime.json` 保存模式、模式请求 ID、配置修订、间隔、已专注时长、下次提醒和提示窗口的剩余时间、墙钟时间及进程随机身份/单调时间锚点。

- 手机配置观察、本机模式变化、远端模式观察、调度建立、提醒到期及提示过期分别记录事实。
- 本机模式缓存保存移入 runtime 锁，避免较早的请求在解锁后覆盖更新模式。
- 触发提示先提交事实；失败回退本次提醒状态，不发送新提示，并在继续调度前恢复未决提交。
- 同一进程优先按单调锚点恢复；跨重启仅在墙钟可信且未倒退时恢复。旧提示窗口已经过去时不重放提示。无可信锚点时建立安全的新调度，不把上个进程的单调时间直接当成当前期限。
- 已专注时长用独立 offset 与当前进程单调起点组合，避免重启后起点变成负值、界面长期停在“启动中”。

计时和输入线程在启用 journal 时显式使用 32 KiB 栈；原助手工作线程已有相同栈配置，Fabric/Agent 执行线程已有更大的独立配置。未启用 journal 时保留原线程创建路径。

## 本地投影修复

读取有实体索引的投影时，先核对对应不可变 envelope、SHA-256、源序号、事件 ID 与实体。普通投影文件缺失或与源文本不同，可由这条已提交事件重建；源记录为删除时维持删除。该过程仅写文件，不执行助手、模式或通知动作。

这避免丢失 assistant.json 后回退到更旧的二进制状态，也避免把越过 journal 的文件变化当成下一条源事实。类型化投影的索引缺失时，先按源序号回查并重建最新索引；只有完整历史里确实没有该实体，才按明确的 legacy_local 快照接纳旧文件。已知源记录或校验文件缺失按 I/O 错误处理，不能伪装成“投影从未存在”。损坏索引仍明确报错；捕获索引、完整远端历史投影和全部事实覆盖继续待完成。
