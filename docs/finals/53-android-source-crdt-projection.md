# Android 副本源事件与 CRDT 视图投影

日期：2026-10-25。任务 05 的投影子阶段。只修改代码、文档并静态回顾，没有运行测试、构建、编译/语法检查、格式化、配置生成或设备。独立 Fabric 源仓库未修改；可靠消息的载体接收与应用持久提交仍分别处理。

## 接通的路径

`BufferSourceCrdtProjection` 严格读取 ReplicaDocumentObserved、CardActionPerformed、LegacyProjectionSnapshot 的 replica/实体/投影文本，验证包装 ID、删除标记、CRDT 结构及完整视图。只使用 `crdt` 寄存器文档；包装中的重复展示卡片不作为第二份权威数据，action 只保留为观察数据，不执行动作。null projection 表示移除一个缓存观察，不推导成卡片墓碑。旧标量 revision 副本仍需专用适配器，不冒充 CRDT。

`BufferCrdtView` 在结构校验之外验证卡片字段、数组、时间、展示、日程、上下文及会话等实际物化输入。它也用于实时合并后的视图检查；实时入口仍允许可合并的部分寄存器映射，源快照入口要求完整可读取文档。相同 stamp 不同值、实体种类冲突、合并后无法形成有效视图都保留原文并报冲突。未分类卡片类型也可正常物化。

源队列通过 repository 回调完成纯合并准备，再调用与实时通道共用的 `applyMergedCrdt`。历史模式关闭 CardDeleted、DocumentMerged 和上下文导入等本地事件追加。合并后的 SQL 卡片、runtime 文档、来源关联和投影状态与外层源投影事务共同提交；失败不确认虚假的投影结果。

## 本机意图与重复协议

已有 CRDT 保持 per-field Lamport 合并与 grow-only 删除。首次从阶段 52 的捕获视图转入寄存器时，先比较来源基线，只为实际已有本机修改保留本机 stamp；不能把未修改的远端捕获视图重标为手机新事实。没有来源基线的旧本机视图采取保守保留规则。原分段文本与完整手机动作进入 CRDT 值，普通显示卡片协议仍沿用原有的小屏动作过滤。

合并准备读取日程时关闭推断缓存写入；已有日期推断缓存也不当成首次源重放的用户编辑。显式修改日程仍由其原事务保存 CRDT。随机本机 CRDT actor 的首次分配属于本机元数据，不生成源事件或执行回执。

卡片已有寄存器后，捕获快照只补齐捕获历史，不再从另一条 SQL 路径覆盖普通卡片字段。明确的捕获删除仍折入已有文档的吸收性删除位，不伪造新的本机寄存器 stamp。实时消息与源观察先后到达，最终都进入同一个寄存器和视图；源观察不因实时通道已经保存过文档而追加替代源历史。

## 删除索引与后台恢复

数据库版本 31 新增本机删除索引、来源文档关联、派生 capture/document 关系和有界扫描检查点。真实本机 CardDeleted 与删除索引同事务提交；旧删除按稳定 event ID 每次最多 32 条补齐，索引和游标一起提交。首次恢复一张不存在的卡片时，旧删除尚未查清则记 waiting_local_history，不能先恢复再等待墓碑。扫描完成后队列继续处理这些位置。

已有源投影也按稳定 ID 分批重新入队，让旧 unsupported_type 获得新适配器的处理机会；升级事务不直接重放全部原文。候选原文仍沿用阶段 52 的批次与软字节边界，额外索引扫描、视图准备不被声称为整个调用的硬资源上限。

因果、音频和投影阶段各自失败退避，不让一个不可读音频永久挡住其他已验证的历史重建。失败阶段单独等待约 30 秒，其他阶段仍可继续有界推进；日志只写固定说明，不输出原文或异常正文。

## Vela 来源与空上下文门禁

静态回顾发现，CRDT 副本构造未保留 origin，导致源发送器无法确认应向哪个对端提供观察。现在认证接收时从真实 peer 建立标记，后续本机动作保留它；本机捕获首次生成副本时使用当前已保存 Fabric 绑定。传入 payload 自报的 origin/local_original 不作为授予转发权限的依据。

已 pin 其他 peer 的副本拒绝直接换 owner。旧副本 owner 未知时，部分更新不能给旧寄存器授予新共享范围；只有同一认证 peer 已提供完整合并文档时，才可绑定这些已由它提供的字节。其他未知来源原文继续保留，不能因为拥有加密通道就推断可以转发。

另一个门禁错误是把空 capture_context/context_summary 的 CRDT 寄存器对象一律当成非空私密字段。现在仅认可严格三字段 counter/actor/value 寄存器里的 null 或空字符串；非空内容、任意对象、错误计数/actor 仍受限。上下文分享范围没有由此扩大，旧不可变原文不被改写。

Vela 的真实删除操作也会在生成新墓碑时清空上下文寄存器和对应摘要，避免吸收性删除仍携带旧私密值、导致删除观察本身一直被拒绝共享。清空属于本次实际文档变更，按既有源事务保存；不是发送时改写旧源原文。
