# Vela CRDT 兼容通道的转发门禁

日期：2026-10-25。任务 05 的隐私与兼容通道子阶段。只修改代码、文档并做静态回顾，未运行测试、构建、编译/语法检查、格式化、配置生成或设备。独立 Fabric 源仓库未修改。

## 问题与修改

源事件发送器已对敏感上下文和副本来源执行检查，但旧 `buffer.crdt.part` 发送器此前会直接序列化 replicas 下的完整记录。仅保护新的源事件通道不能约束这个实际仍在调用的入口。

新增 `buffer_source_privacy.h` 纯检查器，由源事件与 CRDT 兼容发送共用：副本必须有与实际目标 peer 相同的 origin；未知或其他 peer 的来源不因本机编辑变成可转发来源。非空 capture_context/context_summary/context 继续限制发送。只有精确的 counter/actor/value 寄存器、合法计数和身份、且 value 真为空时，空上下文寄存器才可通过。该规则不授予新的敏感上下文转发权限，也不删改不可变原文或寄存器来绕过门禁。

CRDT 选取入口额外验证文件 ID、文档 ID 与 card 种类一致。发送 API 由 Fabric 调用者提供实际认证 peer 和连接 generation，不能使用载荷自报的身份。缓存绑定这两个值，每次生成/重试分片及实际投递排队消息之前重新检查。最终投递还检查当前 active 状态和实际 peer admission；不同连接、不同 peer、失效授权、时钟失败/回退或缓存闲置 30 秒会拒绝继续使用缓存。成功生成重试分片更新缓存活动时间，避免较慢链路或较小 BLE 预算下的大文档被绝对 30 秒期限反复打断。Fabric 单调时钟读取失败返回 0，使缓存检查拒绝发送，不使用未初始化的时间值。

缓存重置、结束和被拒绝的待发送分片会清零后释放。这里只能清除应用持有的明文缓存；已交给可靠载体的字节由既有 Fabric 通道及其生命周期管理，不能声称撤销会收回已交付的数据。

## 回执和分片

CRDT 回执检查完整五字段协议、protocol=1、实际 peer、generation、记录 SHA 及确切分片结束位置；没有生成有效分片时不接受偏移确认。最终持久回执绑定 peer、card_id 和完整记录 SHA。旧 hash-only 回执保留在原处，但不再作为新发送的交付证明；接收端可幂等接受重送。连接代次只约束在途回执，不写入持久交付身份，因此同一 peer 重连仍能复用已落盘的精确交付结果。

最大原文分片仍为 3072 字节；若实际 JSON 帧超过协商预算，逐次缩小原文分片，再按实际帧大小判断。不能容纳最小分片时明确返回错误，不生成越界帧或假回执。解决此前固定 3072 字节分片在合法小预算通道中持续失败的问题。

## 静态回顾范围和剩余工作

逐段核对选取、敏感字段递归检查、缓存重试、最终 Fabric send、会话清理、异步 ACK 和持久回执读取/写入。ACK 处理先在 Fabric 锁内捕获 peer，再在锁外处理，避免从变化中的全局身份推断在途消息来源。CRDT 内部不调用 Fabric 授权回调，不增加反向获取传输锁的路径。现有主机夹具仅调整为新接口参数，未增加或执行测试。

再次读取独立框架 `crates/platform/src/messages.rs` 的 ReliableMessageTransport 契约：send 成功仅表示载体接受，不表示应用持久处理。因此仍以实际应用 CRDT 回执落盘作为兼容通道交付依据；源事件的原文、槽和 blob 回执保持各自语义。
