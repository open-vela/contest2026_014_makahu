# 来源专注、研究观察与追问历史

日期：2026-10-25。任务 05 的下一组 Android 视图适配器。只修改代码和文档并静态回顾，没有运行测试、构建、编译/语法检查、格式化、配置生成或设备。独立 Fabric 源仓库未修改。

## 输入与语义

`BufferSourceObservations` 由既有持久源投影队列调用，处理以下明确的源事实形状：

- focus 投影中的 FocusStateObserved、FocusSessionChanged、FocusModeRequestRecorded 与兼容快照：只解析完整 FocusSession，不执行 operations、pending_operation 或模式请求。
- research 投影中的 ResearchSessionObserved、ResearchDisplayDeadlineReached 与兼容快照：保留严格 schema-v1 的设备观察、剩余时间、显示到期和时钟锚点，不能把它冒充原始 RabbitHoleStarted/Ended 会话。
- conversation/followup 投影中的 ConversationViewUpdated、FollowupContextPrepared、QuestionAnswered、取消与兼容快照：恢复经验证的完整历史轮次及稳定 result，准备/清缓存不推导成答案删除。
- record_json 中已经完成的助手结果：仅适配明确的 followup/focus_session 形状，复用现有纯协议解析器；其他助手、计时器和工具结果继续保持未支持，不解释或执行其指令。

原始 envelope、事件 ID、父引用、源时间和逻辑时钟保持不变。该阶段只从已验证、已 pin owner 的原文物化视图；源原文提交与投影状态仍各自记录，槽不能生成这些视图。

## 持久化与冲突

数据库版本 32 增加按 peer/source/kind/entity 隔离的来源观察表。物化正文、来源事件/位置/时钟与 SHA 绑定，读取核对正文及分页键，并检查源 owner 和投影指纹关联。它们是派生数据，不代替原始 journal 或当前原文健康证明。

专注保存每个来源会话的最新合法快照，保留 session 身份、开始时间和关联实体；较早 source 位置不覆盖较新视图，旧 updated_at、同更新时间异内容、结束后变回 active、已回顾后倒退均拒绝。研究观察同样按真实来源位置处理，已结束的同 ID 观察不被后来的 active 重置。

追问按同一来源中的稳定 capture ID 保留不可变问题/答案/原时间/卡片关联。同一轮原文不同则报告 conflict，不按最后到达覆盖。不同来源分别保留并显示身份。完整轮次在源 cache 的八轮窗口淘汰、清理或重试后仍可由源事实保留；读取本阶段表不改写实时八轮对话缓存。

同一输入最多八轮缓存或九轮 context/history/result。先检查整组冲突，再更新视图；视图与投影结果处于同一个 SQLite 外层事务，失败共同回滚。未知类型、坏字段或冲突保留原文，不能转成空历史成功。全局容量、源文件损坏与派生索引缺失的总恢复回顾仍待继续，不能据此声称全部故障已经覆盖。

## 读取入口与执行边界

专注/研究历史提供“设备会话历史”入口，按来源记录分页查看。专注的 active 显示为“记录时进行中”；研究只显示设备当时看到的状态及剩余时间，不从到达时间补造开始/结束、不恢复倒计时、不切换模式。来源历史没有结束会话、启用提醒或创建待办的按钮。

卡片详情增加设备追问历史，显示完整问题/答案、原时间、设备来源及关联未齐备提示，并可向前翻页。会话和答案每页最多二十项，以稳定逻辑时钟和来源/实体身份组成的键分页；会话使用部分索引，答案使用卡片索引，不依赖可移动的 rowid 或 offset。UI 读取派生正文，不逐项重新加载全部 1 MiB envelope；查询条数有界不等于已经证明设备耗时或整个数据库 I/O 有硬上限。

这组来源视图不写 focus_session_current、rabbit_session、card_conversation 或 CRDT 文档，不调用 appendEvent、模型、日历、健康、通知或旧执行队列，也不把读取后的历史自动转发给其他 peer。它们与本机当前会话及实时通道分别展示，既不伪造原会话，又保留后续显式授权读取的事实依据。

旧 processed focus/followup 通道仍按其原有协议处理。本阶段只读观察不生成该旧协议的兼容完成证明，不因已经存在只读观察就吞掉旧通道原本的业务更新或伪造交付回执。

## 迁移、唤醒与静态回顾

新建数据库创建视图表及索引；旧版本升级只增加派生存储并重置一条有界重放检查点，不在升级事务中解释全部历史。已有源队列随后分批重试旧 unsupported_type。缺少父项时允许自包含视图以 partial 状态展示；父项后来到达仍由现有有界因果队列唤醒，不把部分视图记成完整因果恢复。

源副本事件中的原始 capture_id 可为空，来源会话/追问通过验证过的卡片关联参与详情历史查询，关联字段另存于派生结果，不改写源事件。读取结果保留来源和投影状态。
