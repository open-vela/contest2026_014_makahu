## 严格 envelope 校验

`buffer_source_envelope.c/.h` 对齐 Android `BufferSourceEvent` 的 wire-v1 契约：固定五个顶层字段与十个事件字段、精确 namespace、source/actor/event/capture 身份字符集和长度、有限安全整数、最多 32 个无重复且不含自身的父引用、schema/type/provenance 和 1 MiB 原文上限。根深度为零，值的最大深度 32，与 Android 的词法检查一致。

先做有界递归词法扫描，再让 cJSON 建树。扫描拒绝非 JSON 数值写法、非法转义、控制字符、无效 UTF-8、孤立代理项和尾随内容。解码后对每个对象的键排序查重，覆盖普通键与 Unicode 转义键相同的情况，避免大对象逐对比较。除 payload 的字符串值外，转义 NUL 被拒绝；对象键始终拒绝 NUL。

payload 中合法的转义 NUL 保留在原文中。cJSON 字符串不携带完整字节长度，因此其树只能作为校验后的结构入口，不能把包含 NUL 的 payload 字符串用 strlen 截断后投影为事实。后续类型化投影必须按自己的 schema 拒绝不可表示的字段或使用保留完整长度的解析方式，不能为适配投影而改写源 envelope。

本地 `buffer_source_local_read` 也使用该校验器，核对实际来源和序号。已经在本地 head 范围内的原文或指纹缺失返回 EIO；只有请求超过 head 才返回 ENOENT，避免发送器把历史损坏误判为同步结束。

## 接收入口与磁盘结构

`buffer_source_remote.c/.h` 增加以下存储 API：

- `buffer_source_remote_receive`：要求经传输层取得的 64 位小写十六进制 peer 身份和实时授权回调，返回 stored、duplicate、gap、conflict 与下一期望序号。
- `buffer_source_remote_progress`：只向该来源的已绑定 owner 返回接收进度，未知来源从序号 1 开始；错误或撤销授权不返回可使用的进度。
- `buffer_source_remote_read`：本机后续投影器读取已经提交的精确原文，校验来源、序号和 SHA-256；不执行源 payload。
- `buffer_source_remote_clock`：恢复已经接受的待提交事务，读取持久远端最大逻辑时钟，供本机 journal 分配新时钟。

启用 source journal 才提供远端存储；旧配置的接收/进度/原文 API 返回 ENOTSUP。私有文件目录继续由现有 LittleFS 与权限后端验证。

新增文件均在 `event-journal/` 内：

| 路径 | 内容 |
| --- | --- |
| `remote/<sha256(source_id)>/head.json` | 来源、owner、连续序号、末尾时钟、事件身份和指纹 |
| 同目录的 `000…001.json` / `.sha256` | 精确原始 envelope 与指纹 |
| 同目录的 `000…001.view.json` | 对应事件的本机待投影状态；不保存可执行目的路径 |
| `remote-owners/<sha256(source_id)>.json` | 独立来源绑定与已接受序号，防止 head/流目录缺失后被重新绑定 |
| `remote-ids/<sha256(event_id)>.json` | 跨远端来源的事件身份索引 |
| `remote-state.json` | 版本与已观察最大远端时钟 |
| `remote-envelope.pending` / `remote-pending.json` | 精确待提交原文与小型接收意图 |

路径只由固定前缀、经过验证的身份哈希与整数序号生成。payload 中的文件路径、工具调用、通知、日历/健康回执等只是历史数据，不进入本机执行器，也不复用本机 projection 的目标路径映射。

## 幂等、来源与进度

来源首次接受前预留 owner，提交后保持持久绑定。零条已接受事件的中断预留可以恢复为空 head，但仍保留原 owner；非零来源缺失 head 不能重置为新流。启动回顾会交叉核对流目录和独立 owner 记录，既不因丢失 owner 索引接受已有流的新声明，也不因流目录消失忽略原绑定。

入口拒绝本机 source 回流，以及外来事件占用本机保留的 `evt_<local-source>_` 身份前缀。本机源事件一直在这个前缀内生成；远端不能预占未来本机事件身份。来源 ID 是应用 journal 身份，与 Fabric 公钥不同；这里是直接来源的授权与持久 pin，不是可转交的来源签名，也不授权其他 peer 转发该流。

同 ID 必须同时匹配来源、序号、指纹和精确字节，才是 duplicate。相同序号/ID 的不同内容是 conflict；越过连续 head 返回 gap，不写入未来记录。原生事件的新逻辑时钟必须高于该来源上一个已提交事件；legacy_local 保留已有时钟，不伪造历史顺序。

ID 索引命中后仍回查原文与提交 head。索引缺失时逐个读取有界原文并回填索引，不能把丢失的派生索引当作 ID 从未出现。已知提交范围中的缺失原文、指纹或冲突文件均报错，不能当作空历史。

## 提交与恢复

授权在解析前、进入接收锁后、原文暂存前、提交意图前及返回存储结果前复核。小型接收意图不再把 1 MiB 原文嵌入 JSON，避免再次转义后的体积超出待提交文件上限。

原文暂存成功后才提交接收意图；意图表示当时已有授权的接收决定。随后幂等写原文、指纹、身份索引、待投影状态、最大观察时钟、独立 owner 已接受序号，最后推进流 head，再删除意图与暂存。head 尚未推进但 owner 已领先时，必须有匹配待提交意图才能恢复。head 已提交的重试不重置后续投影状态。

没有意图的暂存文件没有产生提交回执，可以清理；有意图时原文或一致的已写源副本必须存在。恢复失败保留意图并报错，不跳过序号。已接受意图可在断连后完成本机存储，但此时不向已撤销授权的通道返回成功，也不执行任何历史动作。

本机 journal 先持有 local 锁，再进入 remote 锁读取时钟；远端入口先取得本机源快照，释放 local 锁后才进入 remote 锁，remote 持锁阶段不回调本机 journal。授权回调只允许读取独立的实时通信授权，不得回调 journal/store API。网络层接入时仍须审查与 Fabric 锁的关系，不能在载体锁内运行这些存储 I/O。
