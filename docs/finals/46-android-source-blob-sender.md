## 有界登记、迁移与持久状态

数据库升至 28，新建/升级增加：

- `source_event_blob_exports`：已归档原件的稳定登记顺序及完整描述符身份。
- `source_event_blob_export_scan`：升级前 ready 指针的有界扫描位置。
- `source_event_blob_senders`：每个对端已派生的登记位置。
- `source_event_blob_deliveries`：每个对端/事件的独立二进制任务、重试原因、状态和历史 acknowledged 标记。

新原件完成归档后在 pointer/fact 事务中登记。登记序号按“何时完成归档”单调增加，旧 capture 晚归档仍获得新的序号，不会因源事件序号或 capture ID 小于已扫描游标而被漏过。已有登记必须与原描述符完全相同。迁移每批最多四个 capture，只读小型元数据；语义冲突标记需核对，SQLite 存储错误继续使事务失败。新任务的直接登记不依赖迁移是否结束。

每个认证对端每次最多派生八个新登记，任务和对端游标同事务提交。每次最多隔离八个无效候选，随后让出 worker；空闲使用 due/audit 索引，不重新扫描全部源历史或对所有录音计算哈希。候选必须同时具有 ready 指针和本对端的匹配源事件回执。未具备条件的任务保留等待，不跳过源日志顺序。

pending、confirmed 和语义 conflict 表示当前工作状态；独立 acknowledged 标记保留“曾收到对端完整归档确认”的事实。重查失败、原文冲突、显式重试都不清除已有标记，不把历史交付改写成从未发生。

## 实际发送和回执恢复

`VelaFabricEnrollment` Active 时创建发送器，收到 `buffer.events.*` 时交给各自 nonce 绑定的控制器；所有帧继续经既有 SDK 消息通道。六类卡片/源事件/父项/blob 工作轮换发送优先次序，仍遵守已有 runtime、心跳、应用回执与配置优先级。关闭或 generation 变化时释放发送器并清理其持有的音频/分片 ByteArray。

发送前从私有哈希档案读取有界原始字节，通过同一个 no-follow fd 验证类型、权限、大小、EOF、完整 SHA 及 fsync；不使用转码或重新编码的媒体结果。每份原件最多现有 2 MiB 描述符上限。音频快照保留到本份交付结束，不在每个分片重复读取完整音频。

先发 blob.offer，Vela 回 ready 后发 blob.put。每片最多 3072 字节，并预留消息头预算；序号、哈希、总大小、offset、严格 UTF-8/JSON/Base64 和新的 exchange nonce 均绑定本次任务。partial 回执必须恰好推进到本片末尾；restart 重新 offer，并限制连续重启次数。重连不宣称暂存前缀持久，重新 offer 由接收端核对完整档案或从零开始。

每次发送或重传已缓存帧前重新核对当前分享策略和通道授权。读取原件后再次核对，权限不再允许时丢弃待发缓存并保留任务。未知来源不会通过重试按钮取得本机身份或共享权限。

只有精确匹配完整身份、total 和 next_offset 的 blob.received/stored 才进入本地回执提交。既有完整文件可使 offer 直接获得 stored；部分分片、SDK 入队成功、carrier ACK 和源事件回执均不能确认音频已交付。本地确认事务失败会有界重试，之后保留任务重新查询；Vela 会重查完整 SHA 并补交相同持久回执。

每次新的 Active 连接核对已有 confirmed 任务一次；pending/已记录错误的任务优先执行。即使有界批次仅隔离了错误条目，或原件正在后台重查，也不能因一次没有候选就误认为所有旧确认已核对结束。完整回执丢失、对端文件缺失可重新传送相同原件；已有损坏/冲突文件仍由 Vela 保留并明确报错，不自动覆盖为另一份内容。

存储/缺原事件失败退避十秒、无回复一分钟、共享/不支持/冲突五分钟；超出范围的墙钟回退重新进入 due。消息 retry 使用单调时钟。错误日志只使用固定状态码，不打印音频、原文、凭据或异常文本。
