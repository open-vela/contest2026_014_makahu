# Vela 卡片追问

2026-10-20。用户要求停止截图验证，本次不再截图或运行额外测试套件。

## 交互

在 Buffer 卡片详情，原录音按钮显示“追问”。按住录音时绑定当前 card_id；松开提交、滑动取消沿用已有录音行为。普通主页录音继续自动判断意图。详情属于第一页容器，回复直接追加在同一卡片详情，并滚动到新回复，不弹出另一页，也不覆盖原答案、深挖笔记或整理块。

## 上下文与持久化

录音线程在提交前保存主题快照，包含完整的原卡片内容以及最近八轮问答。快照与录音 ID 绑定；后台转写后将其作为数据交给 Agent。指令明确禁止把上下文里的用户内容当作新系统指令，禁止将追问另行分类为 Buffer 卡片。

追问走设备助手处理路径，Vela 已配置的服务负责处理；原始录音不会再被手机重复分类。回复通过 show_answer/ask_user 工具追加到独立的卡片会话记录。录音 ID 负责去重，失败/断电重试保留原轮次。录音取消会删除未提交的上下文，不产生问答或收藏。

MiMo 2.5 的追问请求显式关闭深度思考；回答工具成功保存后直接结束本轮，不再额外调用模型生成“已处理”确认。这只是减少此路径的模型往返，不宣称端到端延迟已经实测解决。

## 手机同步

完成的追问复用 Fabric 原有 processed capture 分片、哈希及回执通道，增加 assistant_complete + followup 的受校验分支，不新增传输方式。手机以事务将轮次追加到原卡片会话，独立于分类结果与用户修改；不存在或已删除的卡片返回冲突，不复活卡片。

手机卡片详情显示问答历史；同步副本携带 conversation，其他 Vela 可合并读取。最近八轮用于展示和下一轮上下文；Vela 原始处理记录及手机 CardFollowupAdded 事件保存完整的单轮问答，滚动窗口不删除源记录。传输重复按录音 ID/快照指纹处理。

只完成必要的 Android APK 与 Vela 编译、更新已有 Windows 模拟器。未自动播放或上传用户旧录音，也未进行本版真实录音、多轮回答及往返同步的端到端验证。正式 LLM 正文流式渲染仍未接入。
