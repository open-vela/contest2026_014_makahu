# 当前对端的父事件定位与范围恢复触发

日期：2026-10-24。任务 05 的父引用发现子阶段。仅修改源码和文档并做静态回顾，没有测试、构建、编译/语法检查、模拟器或设备操作。此阶段实现 Android 向当前 Vela 查询父事件位置；不是完整多来源父链补传。

## 现状与仓库边界

重新读取独立 Fabric 源仓库的 BufferRepository，仍为数据库版本 19，没有现行 source journal。继续修改参赛快照中的应用集成，不覆盖独立源仓库，也未改变通用 Fabric 传输协议。

连续 source 接收本身已经覆盖同一来源较早的原文。父 ID 不存在还可能意味着另一来源未接入、历史损坏、权限限制或非法引用，不能直接跳过游标插入一条定位回复，更不能把“找到位置”当成父原文已入库。现行 Vela 本地父链通常已经被连续范围覆盖；新增定位主要提供显式缺口调查与恢复触发，并为后续多来源接入保留清楚的授权边界。

## 持久查询

Android 数据库从 24 升至 25。新增 `source_event_parent_queries`，以 owner_peer/parent_event_id 为主键保存状态、重试时间和可选的来源/序号/指纹/head 提示；不是 source event、接收游标或交付回执。按 peer/到期时间和 parent ID 建索引，避免每次新原文到达都扫描整张查询表。

`BufferEventHistory` 在处理已提交原生 schema 1 原文时，为尚不存在的父引用登记查询。查询对象只取自已认证远端 child 的持久 owner pin；不向其他设备广播父 ID，也不为未知 schema 或本机记录猜一个远端 owner。旧数据库通过重置派生扫描游标分批发现缺口，不在升级事务中解析所有历史。

`BufferSourceParents.next` 重新检查父原文仍缺失、仍有该 peer 提供的 missing_parent 子记录及当前会话授权。原文实际入库的事务会清理同 ID 的查询，既有因果反向索引继续唤醒子项。定位回复后来才到达时，不会重新创建已经解决的查询。

结果以事务保存，提交前复查授权。available 每 10 秒可再查、无响应退避 60 秒，其余未解决结果退避 5 分钟；新的到期查询优先，避免一个找不到的父项阻塞其他查询。持久到期时间异常超出最大退避窗口时允许重查，避免墙钟回退造成长期挂起。断连只清理 RAM 请求，重启后仍从数据库接续。

## Wire 与 Vela 服务

| 帧 | 公共字段之外的字段 |
| --- | --- |
| `buffer.events.parent.get` | event_id |
| `buffer.events.parent` | event_id、source_id、source_sequence、record_sha256、last_sequence |

公共字段仍为 type、protocol=1、exchange_id。错误沿用五字段固定格式。双方检查字段集合、类型、身份字符、安全整数、协商预算及当前逻辑请求 nonce；重试复用 nonce，新请求重新生成 nonce。

Vela 的 `locate_parent` 仅回答当前本机 journal 的规范 `evt_<source>_<sequence>` 身份，包括本机建立的 legacy 快照。它从 ID 安全推导候选序号，检查十进制规范、溢出和本机 head，再读取真正已提交的原文、独立校验和 envelope，核对原始 event ID。不会为一个未知 ID 扫描全历史，也不读取或转发其他来源的远端原文。

回复来源、位置和指纹前，沿用 source pull 的完整分享策略，包括 schema、私密上下文和副本 origin 限制；授权在整个 handler 入口和返回前再次核对。未开放分享的父项只有 withheld，不泄露其 source、序号、哈希或 payload。已提交原文损坏返回 storage_error，不能伪装为 not_found。所有 I/O 仍在 Fabric 应用 worker、传输锁之外；不破坏现有双向分片缓存。

## 控制器与范围恢复

新增 `VelaSourceEventParents`，在 Enrollment 的已认证 Active 状态创建，与 card/pull/push 四项轮流获得发送优先机会，原配置、回执、runtime 和心跳优先级保持原规则。会话失效和断连会关闭控制器并擦除请求缓冲，迟到的 nonce 回复不会串到新请求。

定位成功首先保存提示，再唤醒现有 pull 查询最新 manifest；如果已经在收分片或确认持久回执，不取消其在途请求。**真正原文仍由连续 source 范围、逐片分享授权、SHA 校验和 journal 事务导入。** 本阶段没有增加乱序插入、越过私密序号或替换旧原文的 API。

- 未到达的位置：继续通过现有连续范围收取；前面的受限项仍可能阻塞，不能因此宣称父链已经补齐。
- 位置低于或等于本机已提交游标，但父原文不存在：登记 history_gap，保留调查状态，不凭提示重建已丢失身份。
- 对端声称本机 source、另一 peer 的已绑定 source，或该来源/序号已有另一个 event ID：登记 conflict，不更改来源 pin、原文或接收游标。
- unavailable/旧固件无响应：持久退避，继续保留 child 和缺口；不返回父链 complete。
- 本机结果事务失败：保留同一请求再查，不能仅推进 RAM 查询游标；busy/storage_error 同样保留请求退避。

指纹和 head 是定位提示，不是原文提交证明，不参与“已接收”判断。父原文真正入库前，因果状态不会变成 linked。来源历史详情显示已找到待补齐、暂未开放共享、来源暂未提供、本机历史缺口及来源信息冲突；这些显示不修改持久因果判定或业务投影状态。
