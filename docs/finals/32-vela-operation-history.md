## 执行入口

启用源 journal 时，`buffer_assistant_execute` 在存储恢复后查询本机源历史，不再把 32 条状态缓存当作完整去重依据。已经提交的请求返回其原始结果及 duplicate，不重新创建计时器、恢复已取消的闹钟或重新执行显示操作。

新请求的源快照保存完整、经验证的参数和原指纹。同 ID 重试除检查操作类型、指纹，还比较完整结构化请求，避免仅依赖 64 位指纹判断不同内容。新建操作只读取该类型真正使用且已经验证过的参数，不访问结构体中未初始化的无关字段。

闹钟的“必须仍在未来”检查移到历史查询之后：已经到期的同一请求仍能取得原回执；只有真正的新请求才检查当前时间窗口，避免回执重试被当前时间误拒绝。

旧二进制迁移只能提供已有的缓存结果及指纹；没有原请求参数时不伪造这些内容。源 journal 启用前已经丢失的操作无法恢复，不声称覆盖那部分历史。

## 索引与提交顺序

`event-journal/assistant-operations/<sha256(operation_id)>.json` 保存原 operation_id 及对应本机源序号。以哈希定位文件，仍校验完整 ID，不能通过点号、冒号或路径片段选择任意文件。

助手投影恢复在写完状态投影及实体索引后、推进源 head 前，保存本次操作索引。重启继续恢复同一 pending；不会因为索引已经写入就跳过未完成的源提交。旧迁移快照为其中保留的缓存操作建立索引；普通后续快照不把旧缓存的复制误当成新的原始请求。

显示请求先保存，再尝试呈现。呈现失败时，原有回退路径追加 `AssistantDisplayFailed`，并将该请求的索引推进到失败事实。查询只有读到这类明确的失败事实、且重试参数完全相同时才允许重新尝试；迟到的成功快照不能掩盖后续失败。断电发生在已提交请求与实际显示之间仍不承诺恰好一次的界面呈现。

## 历史回查与错误

索引只指向不可变源记录。查询校验索引 ID/序号、已提交 head、原 envelope、SHA-256、源身份及投影内容，再提取结果或明确的失败请求，不执行历史内容。

旧 journal 或缺失的派生索引按源序号逆序回查，一次只加载一条有大小上限的 envelope。原生后续状态中的缓存副本没有原请求时，继续查找真正的请求；legacy_local 快照则按其实际可提供的兼容信息处理。找到后按需回填索引。回填缓存失败不把已证实的重复请求变成新任务。

只有完整回查未找到才允许当作新操作；缺失源序号、校验失败、坏索引或无法恢复的 pending 均返回错误。无索引的新 ID 也需要完成该历史检查，因此长历史下有额外 I/O，当前采用有界内存保证正确性，尚未用未经验证的“未命中”缓存跳过历史。全局容量策略仍属于任务 05 的未完成工作。

缺失已提交 envelope 或 SHA 文件会转换为 I/O 错误，与完整扫描后返回的“未找到操作”区分；journal 初始化本身的缺失错误也不能通过该“未找到”分支放行新执行。

## 静态回顾

已检查源 pending 的助手分支、索引写入次序及重复恢复；检查原生请求、缓存淘汰、legacy_local、同 ID 不同参数、明确显示失败重试、索引缺失回查、坏历史及空间不足的返回路径。32 条环形表仍用于当前状态，不能覆盖或清理永久源历史。
