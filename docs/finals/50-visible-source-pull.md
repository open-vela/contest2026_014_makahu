# Vela 到 Android 的可见性传输

日期：2026-10-25。任务 05 的单向网络子阶段；仅修改代码并静态回顾，没有运行测试、编译、语法检查、配置生成或设备。独立 Fabric 源仓库未修改。

`buffer_source_wire.c` 接入显式 visibility-v1 manifest、read、slot.accepted 和 original.accepted。槽帧只含协议/请求标识、source、sequence 和随机 token，不携带事件 ID、类型、时间、SHA 或大小。原文分片另带完整 SHA、总大小、偏移与 token，沿用授权通道和预算。未知或关闭配置不假装支持。

Android Enrollment 使用 `VelaVisibleSourceEventPull`。先协商，只有未启用新 profile 的旧流可以回退；已持久保存槽的来源拒绝旧 profile 导入。接收方先事务保存槽或完整原文，再分别确认，槽确认不能形成原文或 blob 回执。重连比较双方实际覆盖进度；本机已保存原文可重新提供精确证明，同一 source 的接收历史倒退明确报错。

新覆盖与旧 held 位置交替处理，已有槽按序轮询，完成一轮后退避；检查点核对期间更频繁刷新 manifest。刷新请求穿过在途分片保留，父项定位可触发下一轮核对。原文确认遇到当前不可分享策略时，改为确认槽，保留本机原件和历史完整回执；不会重复尝试同一不可分享 SHA 形成循环。

Vela 每次请求检查活跃授权，发送前再次检查；缓存绑定 peer、generation、source 和 sequence。原文策略依据不可变数据和绑定对端判定；拒绝原文先于比较对端 SHA，避免新证明接口成为受限内容的哈希查询器。缓存空闲超时、时钟失败或倒退均清理，忙碌时也执行检查。发送侧 offered 只在缓存首次提供时登记，载体 ACK 不代表应用持久提交。

历史详情只展示实际保存的原文；页面相关来源存在 held 位置时显示来源级提示，不伪造属于某张 Capture 的隐私事件，也不宣称已完整同步。元数据 API 不触发业务执行器。

静态回顾覆盖字段集合与数量、nonce、大小/分片/Base64/完整 SHA、重复帧、事务失败、权限撤销、原文证明丢失、双方覆盖落后、旧固件回退及公平补发。此阶段没有新增数据库 schema 或 C 编译单元。

本阶段仅接通 Vela→Android。Android→Vela 仍使用旧 sender，受限位置会阻塞；业务投影、完整父链、多成员及容量/故障总回顾仍待完成。任务 05、06、07 保持未完成。
