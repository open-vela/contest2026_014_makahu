# Android 完整文档源观察与接收范围

日期：2026-10-25。任务 05 的 Android 源写入子阶段。只修改代码和文档并静态回顾，未运行测试、构建、编译/语法检查、格式化、配置生成或设备。独立 Fabric 源仓库未修改；载体 ACK 不作为应用或视图持久提交证明。

## 补入完整可重建内容

此前 DocumentMerged 主要记录 ID/clock，不能从该事件本身还原寄存器字段。现在增加 CardDocumentObserved、CalendarDocumentObserved；新 DocumentMerged 也带完整文档。payload 固定为 id、clock、document、audience。原有寄存器 actor/counter/value 与删除位保留，不用源日志逻辑时钟生成另一套寄存器 stamp。

卡片导出观察、日程本机输入及实时 CRDT 合并保存当前实际文档。卡片导出改为整体 SQLite 事务，文档、接收范围、原始源事件和观察检查点共同提交；不是先提交 runtime_settings 后单独补日志。没有检查点的旧文档在下一次实际导出/更新时建立当前观察，不伪造升级前的每一次历史变化。

检查点指向实际本机源事件。重复导出先读取并验证原文、SHA、源身份/位置和完整文档，文档及 audience 都相同才复用；新观察成功追加后核对新的 journal head，再保存指针。源原文丢失/损坏不被当作“没有变化”。观察本身不触发分类或外部执行。

Android 的源 CRDT 适配器已识别这三个类型，验证完整 payload、文档种类与 clock，不把 audience 当作接收端授权或可转交来源签名。Vela 现有源协议可以持久接收这些原文，但本阶段没有实现 Vela 的远端文档投影器，不能据此声称设备已能仅靠新源事件重建卡片。

## 来源范围与转发

数据库版本 33 增加文档范围及观察指针。范围分为本机原件、绑定 peer 和未知；范围元数据绑定 document ID 并核对 SHA。实际 Capture 来源可提供本机/对端依据；认证接收和源投影传入真实 peer。已经绑定其他 peer 的文档不能直接改 owner。

旧 owner 不明且包含未知旧寄存器时，不从部分输入推断新的转发权限。认证 peer 提供了完整合并文档时，可以约束为向该 peer 返回其已提供的字节。新鲜本机日程输入只有提供全部保留字段时才可建立本机范围，不把未知额外字段归为本机原件。未知范围继续保留，不因有连接或有用户编辑而默认可转发。

源发送器现在给逐片分享判断传递目标 peer。原始观察的范围与当前范围均须允许目标，proof 和缓存重试也检查；未知、其他 peer 或来源元数据损坏均不发送完整原文，visibility 槽仍只提供覆盖。此阶段不会为旧 unknown 观察自动追认历史转发授权；完整的用户范围授予与多成员生命周期仍属后续工作。

实时卡片 sender 同样按实际目标检查范围。来源只读会话/追问视图没有因此被塞进 CRDT 或转发缓存。

## 上下文与系统日程权限

完整文档可能含捕获上下文，不能沿用“非 CaptureContext 类型一律可发”的旧判断。新文档发送前验证完整视图，递归检查敏感字段，只认可严格寄存器里的空值，不能用任意三字段对象隐藏私密内容。

非空上下文须与本机真实 CaptureContextCaptured 事实核对，按当前分享开关及位置/日程权限形成允许视图；摘要必须与允许的上下文说明一致。仅 payload 自报 source_device 或 imported/shared_context 不能证明是本机采集。旧的待采集/来源未核实或不再匹配当前允许视图的观察仍受限，不因补传而改写其原文。系统日程文档也在发送前复查 READ_CALENDAR。已经发出的字节与已有完整回执不会因当前撤销而被伪称撤回。

## 实时接收与源历史的交错

实时 CRDT 接收把当前认证 peer 和活跃授权检查带入合并事务；首次、每片、提交与回执边界检查授权。分片缓存区分 peer，规范校验 UTF-8、JSON 和 Base64；临时字节在退出时清理，撤销时清理组装缓存。载体和应用回执仍分别处理。

源投影路径仍关闭本机观察追加，避免一次源重放立即再生成替代源事件。后续实际导出如需要建立本机观察，明确命名为观察，不能将其当成原始远端 envelope。实时合并有真实文档快照，历史接收继续保留原始来源和因果图。
