# 无损多层记忆、持续观察与自主功能生长：实施计划

日期：2026-10-31。状态：**待实施；已完成现行代码盘点，尚未实现本计划新增能力。**

依据：用户要求在现有 Buffer 基础上补齐“无损多层记忆系统”和“持续观察生活后，自主发现需求、主动搭建新功能”的能力。沿用 [总任务清单](../buffer-completion-tasks.md) 的编号、检查项、代码回顾及单列验收格式。

本次只写计划，不修改业务代码，不启动构建、测试或模拟器。后续实施按会话已有的构建测试授权执行必要验证；历史专题中“仅静态审核”的阶段约束不替代后续授权。历史测试通过不作为本计划新增能力的完成证据。

## 目标与完成口径

完整链路为：

```text
已授权观察 → 原件提交 → 事实/情景/长期记忆 → 需求假设
→ 功能规格 → 工作流或代码包 → 独立验证 → 预览/策略内试运行
→ 执行回执 → 效果评估 → 保留、修改或回滚
```

- 无损指已成功提交的原件保留精确字节、来源和校验依据；摘要、索引与派生记忆可回到原件核查。摘要本身不承诺可逆，存储也不承诺无限容量。
- 将“原件完整保存”“派生层可重建”“检索能够找回相关细节”分别验收。保留音频不等于已正确理解音频，也不等于模型每次都能召回相关内容。
- 通用功能生长必须能处理未预置的需求，产生实际可运行的工作流、界面或插件。范围包含新增逻辑与代码生成，不能只扩充固定建议文案或几个内置模板。
- 实际生成范围取决于设备接口、已授权数据、可用执行器和运行资源；缺少接口时记录所需新适配器及不能完成的部分，不能虚报安装、执行或收益。
- 自主程度由用户预先设置的策略决定。允许在既定权限、费用和打扰预算内自动发现、构建、验证及试运行；新增权限或超出策略的动作单独进入待批准状态，不对范围内的每次运行重复询问。
- 原始观察、模型推断、用户确认、执行记录和授权分别存储。同步记忆或生成包不恢复执行权，不把推测升级为已发生事实。

## 02 原件保真、恢复与删除语义

依赖：01。复用 journal/blob，不另造备份事实源。

- [ ] 逐类建立“原件 → 派生层 → UI → 模型输入”的恢复矩阵，补齐缺失适配器，区分运行授权表与可丢弃缓存。
- [ ] 原件/音频继续精确校验；缺失、损坏、权限保留槽与尚未交付分别表示，不能由摘要或缓存反造原件。
- [ ] 实现派生层可重建、断点续建、坏记录隔离、迁移中断恢复及版本升级后的重算；原件损坏时显示不可核实，不把缓存当成健康原件。
- [ ] 定义冷热存储及归档清单，记录原件位置、校验、已确认副本和恢复状态；外部归档位置需要可用性证明，不能只存一个路径就删除唯一原件。
- [ ] 存储紧张时优先释放可重建索引和缓存；无法提交的新输入明确反馈。不得静默删除唯一原件，也不得承诺尚未成功落盘的输入已经保存。
- [ ] 区分内容更正、界面归档、停止用于记忆、撤销共享和永久删除；实现用户要求的删除策略及跨设备墓碑，不用“不可变”拒绝用户删除。
- [ ] 删除/撤权同时处理摘要、向量/关键词索引、检索缓存、候选需求和未执行任务；离线设备展示待同步状态，不能声称未连接设备已擦除。
- [ ] 若引入加密归档，明确密钥保存、恢复和失效策略；应用删除不承诺底层闪存的物理安全擦除。

验收：丢弃全部可重建索引后找回原文、事实和已支持视图；中途强杀可续建；损坏/超限不伪造成功；用户删除后旧设备重连不能使内容重新出现。

- [ ] 建立事件触发和周期整理任务：新事实增量、情景结束、日/周/月回顾；使用持久队列、租约、输入修订、模型/提示版本及可恢复 checkpoint。

验收：旧偏好被用户纠正后，相关回答和需求停止使用旧结论；跨多次摘要仍可定位原始细节；缺少记录时输出未知，不生成缺乏依据的生活模式。

## 08 功能代码生成、隔离构建与验证

- [ ] 定义 `CapabilityPackage`：规格、源码/工作流、依赖与运行时版本、权限清单、UI、状态迁移、测试、包摘要、构建来源和回滚信息。

- [ ] 生成插件通过受控 API 读取记忆、维护自身状态、创建表单/视图及请求动作；不直接获得应用数据库、原件目录、宿主 shell 或任意系统 API。

- [ ] 能由A2UI与已有动作表达的界面和功能直接组合生成；只有新增计算逻辑、状态机或设备适配确实超出已有能力时才生成新插件/原生代码。A2UI不替代后台观察、工作流持久化、授权、任意代码隔离或回滚。

验收：至少生成一个未预置的新逻辑插件和一个新界面；实际构建并运行；越权、超时、资源耗尽和恶意依赖测试拒绝发布；系统能根据独立失败结果修改后再验证。
