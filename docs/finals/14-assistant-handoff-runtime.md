# Windows 模拟器助手受理排查

日期：2026-10-19。Android 17 与 Vela 均运行在 Windows；保留配对和用户数据。

## 复现与证据

用户在 Vela 说“设置一个三十秒计时器”。手机收到 2920 毫秒 WAV，样本峰值 3869，实际转写为“设置一个三十秒计时器。”。分类选择助手后，任务仍停留在 `classification_jobs.pending`，失败事件只记录“设备未受理助手任务，原记录已保留”。

在设备助手回执错误分支设置单点调试断点，捕获真实回执：

```text
state=failed error_code=not_coordinator
```

在设备提交助手任务的协调者校验入口捕获：

```text
requested_term=7 device_term=8
bound=1 connected=1 peer_ready=1 storage_failed=0
```

同期设备状态显示 Agent 已验证、Fabric 已连接、协调者为手机。拒绝由轮次不一致触发，不能归因于转写失败或设备未配对。排查结束已分离调试器并关闭调试监听。

## 原因与修复范围

Android 只处理心跳发送者宣称自己为协调者的领导声明，遗漏了 Vela 报告更高轮次、但领导者仍为本机手机的情况。手机继续携带旧轮次发送助手任务，设备严格校验轮次并拒绝，重试无法自行收敛。

修复应在 App 中处理经认证、属于当前成员关系且通过新鲜度校验的更高轮次观测，并使旧任务租约失效；不得取消设备的轮次校验。App 还需要以受限错误映射区分协调者失效、来源冲突和存储错误，避免把任意远端内容作为错误文本展示。

## 验证状态

录音、蓝牙传输、真实 ASR 转写已验证。App 轮次收敛修复及自动恢复原任务的运行验证进行中；本记录暂不宣称计时器创建、响铃通过。
