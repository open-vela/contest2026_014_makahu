## 原子入队与有界恢复

本机 journal append 与新远端原文导入，在原有事实事务中登记 `source_event_history_work`。失败会回滚事实及入队，不存在先报告导入成功再遗漏历史工作的窗口。重复接收不重写已存原文；既有持久队列或迁移扫描继续接续。

派生表职责如下：

| 表 | 内容 |
| --- | --- |
| source_event_history | 原始指纹、已核对的类型/时间/逻辑时钟及因果状态 |
| source_event_history_parents | child/parent 原始事件 ID，对 parent 建反向索引 |
| source_event_history_work | 尚待核对的事件身份 |
| source_event_history_changes | 父事件变化的子项唤醒游标 |
| source_event_history_scan | 旧历史迁移的稳定 event ID 游标及完成标志 |

旧历史每批扫描最多 8 个身份、处理最多 8 个原文；有效原文字节达到 2 MiB 后结束本批，每条原文仍受 1 MiB 上限约束。坏记录也受批次数限制。这些是条数、字节和内存范围，不是实际耗时承诺。迁移游标使用稳定 event ID，避免 VACUUM 改变隐式 rowid 后遗漏旧记录；迁移期间新增的较小 ID 仍通过事实事务直接入队。

一个父事件可以被很多子事件引用，因此入库事务只登记变化，不展开全部子项。worker 每批处理一个变化分页，最多唤醒 32 个 child；游标与入队同事务提交。父状态再次变化会重新登记扫描起点；新 child 登记关系时直接读取当时的父状态。没有子项的叶事件不制造空的变化队列。

正常积压每 100ms 接续下一批，空闲每 5 秒检查；存储异常保留队列并退避 30 秒。日志只有固定状态，不输出原文或异常中的 payload。worker 可关闭，关闭后不继续安排任务。

## 因果状态与限制

处理原文时重新执行严格 envelope 校验，并核对原文 SHA、事件 ID、source、sequence、逻辑时钟、capture 及本机/远端持久提交游标。远端记录必须有合法 owner pin，不能将游标之外的孤立行作为已提交历史。原文或索引不一致会保留为 corrupt 状态，不把错误伪装成没有历史，也不因一条坏记录让整个批次永久停在同一行。

原生 schema 1 记录的每个父项必须已存在、已经过因果索引核对，且父逻辑时钟严格小于子项。父指纹或缓存时钟与源表不一致时，重新安排该父项核对。未知 schema、旧兼容原文和异常因果关系均不能变成 linked。

| 状态 | 含义 |
| --- | --- |
| linked | 原生记录的已知因果元数据齐备 |
| missing_parent / waiting_parent | 父原文缺失或尚未整理完毕 |
| blocked_parent | 父项是未支持、兼容或异常状态 |
| unsupported_schema | 保存了原文，但当前版本不支持其事件语义 |
| legacy | 明确保留旧兼容历史，不伪造其原生因果证明 |
| invalid_clock / corrupt | 时钟关系异常或原文/索引/提交证据不一致 |

父原文后来入库，或父状态核对发生变化，会通过持久反向索引重新检查子项。原生环状父链不能同时满足严格递增时钟，因而不会全部变成 linked。兼容历史只归档，不把它当作原生父链已完成重放的证明。

**linked 仅描述历史因果元数据，绝不表示卡片已重建、业务投影已完成或外部动作已执行。** 现有 `source_event_projections` 仍保留原本 pending；本阶段没有向旧 events、captures/cards、执行任务、日历、健康或通知队列写入历史副作用。未知事件类型只显示通用归档标签，不解释 payload。

## 用户读取与重新核对

卡片详情增加“查看来源历史”，展开后才在 IO dispatcher 读取索引。显示来源类别、原始时间、固定类型标签与可理解的因果状态；不在界面暴露协议字段或原始 payload。无法读取显示重试状态，不显示为空历史。未知 schema、待处理和损坏项不会套用已支持事件的语义标签。

本机源历史可以关联本机卡片；远端历史还必须满足其已绑定 owner 与该 capture 的 `source_device` 相同。不能仅凭外部 peer 使用了相同 capture ID，就将其记录混入另一来源的详情。

每页最多 32 条，按 logical clock/source/sequence 稳定排序，提供“查看更早记录”和“回到最近记录”。分页使用同一稳定三元组，不以 offset 翻页；新事件到达不会让旧页因位置变化而跳过原有记录。此顺序是逻辑顺序，原始墙钟时间仅用于显示。

读取异常或原始证据需要核对时，用户可以重新安排派生索引扫描。该请求只重设迁移游标、按需创建派生表；不会删除源记录、清空业务状态、重放外部动作或把错误原文自动改写为正确。长历史仍由原 worker 分批接续，不能把请求已登记当作核对已完成。
