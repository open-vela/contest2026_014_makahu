日期：2026-10-24。任务 05 的后续实现及静态回顾。没有运行测试、构建、检查程序、模拟器或实机；整个任务 05 仍未完成。

## 追问捕获与原回答

类型化 journal 新增 `followup`（`records/<capture>.context`）、`conversation`（`conversations/<card>.json`）及 `research`（`research.json`）。目标仍由固定类型与受限 ID 推导，迁移仅为实际旧文件建立 legacy_local 快照。凭据、工具检查点和其他 records 辅助文件不会因相同目录而误判为追问记录。

`buffer_followup_prepare` 先检查同一 capture 是否已有相同卡片的上下文，重试保留原主题和历史快照，不用之后编辑过的卡片覆盖。另一个卡片复用同一捕获 ID、坏上下文、坏源历史或分配失败均返回错误，不退化为无上下文问题。主题读取仍使用排除捕获上下文摘要的模型入口。

回答路径现在先将原问题、原回答、捕获时间和卡片关联保存到该 capture 的 result，并追加 `QuestionAnswered`，然后更新最近八轮展示缓存。若缓存失败、重启或八轮窗口已淘汰该项，重试仍使用 capture 中的原结果。旧固件若已经保存缓存而尚未保存 result，按匹配的原问题、时间及捕获 ID 接续第一次回答，不用新的模型回答替换。

缓存只保留完整的最近轮次，按时间与稳定 ID 排序；编码达到大小上限时减少旧展示轮次，不截断原问题、原回答或原主题。原始 result 和不可变源事件不随展示窗口淘汰。同一捕获在不同视图中出现不同问题/回答/时间时明确报冲突。

录音取消通过 journal 提交上下文删除事实，清理失败反馈等待恢复；已完成的 result 不接受录音取消路径删除。新准备、完成及取消的恢复仅写文件，不执行 LLM、助手或新的录音动作。

## 历史发现与修复

新增 `buffer_source_projection_ids` 从已提交源事件枚举本机实体身份，包含删除身份。每次最多 32 个按 ID 排序的结果，验证源序号、原文及 SHA；缺失源记录或校验文件是错误，不能当作枚举结束。它不是远端事件导入、授权转发或执行入口。

展示与后续捕获的上下文合并会查找各 capture 的稳定 result，不仅依赖可能不完整的八轮缓存。即使普通上下文文件或实体索引丢失，也能先从源历史发现身份，再由现有投影修复路径恢复原文。关闭 journal 的兼容路径从本机 context 文件收集已有结果，不声称能恢复旧固件已经丢失的历史。

枚举采用有界内存，但每页仍扫描本机源历史，长历史下存在额外 I/O；尚未以不完整的磁盘目录枚举替代源完整性。界面将历史读取错误反馈为错误，而非默认当作没有对话。

## 研究会话观察

接入 `buffer_sync_research`、初始化恢复和独立计时线程。已认证业务入口提供的会话 ID、主题、active、reason 和有效期限保存为 `ResearchSessionObserved`；这是本机收到的观察，不冒充手机原始 `RabbitHoleStarted/Ended` 事件。

相同会话的重发不延长原有期限。只有实际会话内容、有效期限或显示到期状态变化才追加新观察，普通倒计时刷新不持续写入事件。计时线程及先发现到期的状态轮询均能保存显示到期事实；显示到期不擅自把手机 active 改成 false，也不调用远端结束或执行接口。

检查点同时保存进程身份、单调时间及可信墙钟锚点。当前进程优先用单调时钟恢复；跨重启时只在墙钟可信且未倒退时恢复剩余期限。活动会话缺少可信锚点、模式仍待本机确认或不属于当前研究模式时，等待新的手机状态，不重放旧倒计时。收到的新会话仍需通过原模式门禁及 ID/大小/状态校验，包含原协议允许的点号 ID。
