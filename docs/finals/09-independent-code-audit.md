## 已确认问题

### P1：Fabric 会话建立后，模式、专注提醒与研究状态没有可工作的双向同步

**触发条件：** 手机与 Vela 已通过 Fabric 配对并建立会话，随后在任一端切换模式，或修改专注提醒/研究 session。

**影响：** 两端继续使用各自本地状态；专注提醒计时和研究 session 也会分叉。旧 LAN 响应仍能解析 `mode`、focus 与 research，但 Fabric 绑定后 LAN 同步线程明确跳过旧协议；所以“应用层卡片已迁移”并不意味着这些节奏状态也已迁移。

**调用链与根因：** 旧 LAN 的 `display_cards.updated` 在 [buffer_wire.c:808](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_wire.c:808) 解析 mode/focus/research，并在 [buffer_wire.c:853](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_wire.c:853) 至 [buffer_wire.c:900](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_wire.c:900) 应用；但 Fabric binding 存在时 [buffer_wire.c:1823](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_wire.c:1823) 至 [buffer_wire.c:1833](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_wire.c:1833) 将这条同步路径禁用。Fabric 发件循环只轮询 coordinator、卡片动作、待处理录音和已处理记录，没有 pending mode/runtime 状态发送：[buffer_fabric.c:579](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_fabric.c:579) 至 [buffer_fabric.c:587](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_fabric.c:587)。入站分发也没有 `buffer.runtime.state` 分支，未知类型落入 OOBE 解码：[buffer_fabric.c:422](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_fabric.c:422) 至 [buffer_fabric.c:479](/home/simon/vela/contest2026_014_makahu/app/buffer_app/buffer_fabric.c:479)。

当前 Android working tree 新增的 [VelaRuntimeProtocol.kt:7](/home/simon/vela/contest2026_014_makahu/foundation.fabric/apps/android/buffer-app/src/main/kotlin/com/mocharealm/foundation/fabric/buffer/data/device/VelaRuntimeProtocol.kt:7) 和 [VelaFabricEnrollment.kt:160](/home/simon/vela/contest2026_014_makahu/foundation.fabric/apps/android/buffer-app/src/main/kotlin/com/mocharealm/foundation/fabric/buffer/data/device/VelaFabricEnrollment.kt:160) 尝试发送 runtime snapshot、处理 `buffer.mode.change`，但这些改动尚未构建、测试或安装，且 Vela C 端相应接收/parser/ACK 尚不存在，不能视为修复完成。

**建议：** 完成单一、版本化且带持久 revision/ACK 的 Fabric runtime 协议；把 mode、focus reminder、research session 作为同一受限状态快照同步；为 phone→Vela、Vela→phone、断线重试、旧 revision、重复消息和本地未确认变更补端到端测试。

### P1：Vela 本地卡片后续操作无法回写 Android

**触发条件：** 一条 Vela 处理的 capture 已在手机生成卡片；用户随后在 Vela 对该本地 `vla_` 卡片执行归档、完成、稍后、提醒、研究或删除。

**影响：** Vela 会持久化新的卡片状态，Android 却保留旧状态，造成两端卡片/删除语义不一致。Android 来源卡片的反向动作走独立的 `buffer.card.action` 路径，不受此缺陷影响。
