# Buffer 手机端与 openvela 设备端文档草案

版本：v0.1  
范围：Buffer 上层应用、Android/iOS 手机端、openvela Gemini-S1 展示架设备端、以及两者与底层同步层/设备网格的接口边界。

---

## 0. 总体定位

Buffer 是“意识与现实之间的缓冲区”。它接住用户随时产生的灵感、问题、待办和生活记录，将它们先保存为原始事件，再由本地规则与 LLM 协处理生成分类、答案、提醒、卡片和周报。

手机端是 Buffer 的主力交互端和日常运行端。它负责语音捕捉、事件本地化、通知、日程/健康系统集成、主设备协调、卡片生成与同步。

openvela Gemini-S1 设备端是 Buffer 的桌面展示架和快速语音入口。它不承担完整语义理解和复杂同步逻辑，只负责：按键语音输入、离线缓存、展示少量卡片、专注/睡前提醒、与手机/主设备同步。

底层设备网格负责设备身份、发现、配对、能力声明、资源传输、事件同步和任务调度。Buffer 只是运行在这套网格上的一个应用命名空间。

---

## 1. 术语

### 1.1 Capture

用户通过语音、文本、快捷键或设备按钮产生的原始输入。Capture 必须保留原始内容，不应被 LLM 的分类结果覆盖。

### 1.2 Event

系统中所有可追溯变化的基本单位。包括原始捕捉、转写结果、分类提案、用户确认、卡片下发、提醒触发、任务完成等。

### 1.3 Spark

灵感、设想、概念、创作冲动、项目苗头。Spark 不等于待办，不应默认转成任务。

### 1.4 Question / 十万个为什么

用户产生的问题。可以被快速回答，也可以进入“灰色未解区”，等待每周兔子洞时间处理。

### 1.5 Answer Box

问题冷藏和回流区域。用于保存已答问题、未解问题、研究入口和上下文。

### 1.6 Shelf / 灵感架

灵感冷藏、发酵与回流区域。用于展示和整理 Sparks。

### 1.7 Display Card

下发给手机首页、Vela 展示架、睡前模式、专注模式的轻量展示对象。Card 是派生视图，不是事实源。

### 1.8 Coordinator

当前负责 LLM 调用、复杂分类、周报生成和跨设备编排的设备。Coordinator 不是唯一数据库；事实源仍是多设备事件日志。

## 2. 数据原则

### 2.1 原始记录不可丢

任何语音、文本或设备事件进入系统后，必须首先保存为不可变原始事件。

LLM 分类、转写、摘要、标签、答案都只是派生事件。

推荐事件链：

```text
CaptureCreated
→ CaptureTranscribed
→ ClassificationProposed
→ ClassificationAccepted / ClassificationEdited / ClassificationRejected
→ SparkCreated / QuestionCreated / TaskProposed / LifeLogCreated
```

答案箱的后续操作也必须追加事件，例如 `QuestionAnswered`、
`QuestionResearchNoteAdded` 和 `QuestionExternalLinkAdded`。研究笔记与外部链接
属于问题卡的派生视图，不能覆盖原始 Capture；外部链接只允许用户确认后保存的
HTTP/HTTPS URL。

### 2.2 分类是提案，不是事实

LLM 不直接写入最终业务对象。它只能生成 proposal。用户确认或本地策略自动接受后，才生成正式事件。

### 2.3 同步事件，不同步最终状态

设备间同步以 append-only event log 为主。每台设备可本地 materialize 出自己的视图。

### 2.4 Card 是视图，不是数据源

Vela 设备和手机首页展示的是 Display Card。卡片可被刷新、删除、重排，但不应反向覆盖原始事件。

### 2.5 用户主权优先

所有高风险动作必须有本机权限和用户确认，例如：写入日历、写入 Apple Health、删除历史、启用新 Skill、跨设备访问敏感资源。

---

## 3. 手机端功能文档

## 3.1 手机端定位

手机端是 Buffer 的常用入口、通知中心、本地数据库节点、系统 API 桥接器和可选 Coordinator。

Android 手机通常更适合承担后台任务、通知和日常采集。iPhone 更适合作为 Apple Health、快捷指令、部分 Apple 生态 API 的桥接设备。

手机端不应假设自己永远在线，也不应假设自己永远是主设备。

---

## 3.2 快速输入

### 3.2.1 语音输入

支持入口：

- App 内长按录音按钮
- 锁屏/通知快捷操作
- 桌面 Widget
- 耳机按钮或系统快捷入口，视平台支持情况实现
- 来自 Vela 设备同步的语音 Capture

交互：

```text
按住 → 开始录音
松手 → 结束录音
保存原始音频 → 创建 CaptureCreated
```

可选模式：

```text
单击开始 → 再次单击结束
```

录音结束后，手机端需要：

1. 写入本地 Capture；
2. 保存音频 blob；
3. 创建待转写任务；
4. 若当前设备不是 Coordinator，则同步给 Coordinator；
5. 若离线，则进入 pending queue。

### 3.2.2 文本输入

支持快速文本输入，用于不方便说话的场景。

文本 Capture 与语音 Capture 使用同一套事件链，只是没有音频 blob。

---

## 3.3 本地事件库

手机端必须维护本地事件库。

建议存储：

```text
事件表 events
blob 表 blobs
同步游标 sync_cursors
设备表 peers
任务表 local_jobs
卡片表 display_cards
权限表 permission_grants
派生视图表 materialized_*
```

事件字段建议：

```json
{
  "event_id": "uuid/ulid",
  "app_namespace": "app.buffer",
  "device_id": "...",
  "actor_id": "user/local/llm/system",
  "logical_clock": 123,
  "created_at": "...",
  "event_type": "CaptureCreated",
  "payload": {},
  "parent_event_ids": [],
  "schema_version": 1
}
```

---

## 3.4 转写与分类

手机端可以支持三种处理策略：

### 本地轻量处理

用于隐私敏感内容或网络不可用场景。

能力：

- 简单关键词分类
- 时间表达式抽取
- 待办识别
- 标签匹配
- 音频时长、音量、空白段检测

### 远程 LLM 协处理

由 Coordinator 调用 LLM。手机端如果不是 Coordinator，只提交任务请求。

LLM 输入必须最小化，输出必须结构化。

示例：

```json
{
  "task": "classify_capture",
  "raw_text": "我突然想到 Buffer 就像意识和现实之间的缓冲区，明天记得写一下 Vela 文档",
  "allowed_outputs": ["segments", "type", "title", "summary", "tags", "confidence"]
}
```

返回：

```json
{
  "segments": [
    {
      "type": "spark",
      "title": "意识与现实之间的缓冲区",
      "summary": "Buffer 的核心隐喻。",
      "tags": ["Buffer", "意识", "产品概念"],
      "confidence": 0.91
    },
    {
      "type": "task",
      "title": "写 Vela 文档",
      "time_hint": "tomorrow",
      "confidence": 0.84
    }
  ]
}
```

### 用户确认

涉及日历、提醒、健康数据、删除、长期规则启用时，必须进入确认流程。

---

## 3.5 灵感架 Shelf

手机端需要提供完整 Shelf 界面。

核心功能：

- 查看所有 Sparks
- 标签过滤
- 时间线浏览
- 搜索
- 关联旧想法
- 标记状态：冷藏、发酵、转项目、归档
- 生成 Display Card 下发给 Vela
- 从 Spark 创建项目、文章、代码任务或兔子洞主题

Spark 数据由事件派生，不应直接覆盖原始 Capture。

当前 Android MVP 已实现 Spark 标签编辑、本地过滤、发酵状态和旧想法关联，也支持问题卡关联 Spark/生活事件；这些操作记录 `CardTagsUpdated`、`SparkRelatedCardAdded`/`SparkRelatedCardRemoved`、`QuestionRelatedCardAdded` 和 `QuestionRelatedCardRemoved`。Spark 还可以生成带来源关联的项目草稿、文章草稿、代码任务或兔子洞主题卡，并记录 `SparkDerivedCardCreated`；完整的外部项目管理器仍属于后续工作。

---

## 3.6 答案箱 Answer Box

手机端需要提供完整 Answer Box。

问题状态：

```text
quick_answered      已快速回答
unanswered_gray     灰色未解
rabbit_hole_candidate 兔子洞候选
researched          已深入研究
archived            已归档
```

功能：

- 查看已答/未解问题
- 每日睡前展示精选问题
- 每周抽取兔子洞候选
- 明确标记问题为已深入研究
- 给问题追加研究笔记
- 关联到 Spark、生活事件、外部链接和文章

注意：不能可靠回答的问题应被明确标记为未解，不应生成伪确定答案。

---

## 3.7 待办与日程

手机端负责把任务提案变成现实日程。

流程：

```text
TaskProposed
→ 用户确认时间/优先级/日历
→ CalendarWriteRequested
→ 本机系统 API 执行
→ CalendarEventCreated / CalendarWriteFailed
```

规则：

- 不自动把所有念头变成待办；
- 没有明确时间的任务进入 Inbox；
- 课程/学习相关可写入课程表日历；普通事件写入默认日历；
- 写入外部日历必须可撤销。

---

## 3.8 Life Log 与健康数据

手机端需要支持生活记录分类：

- 饮食
- 饮水
- 运动
- 睡眠
- 情绪
- 症状
- 学习/专注
- 旅行/地点事件

饮食可做营养估算，但必须标注估算性质。

HealthKit 或其他健康平台同步应采用本机权限模型，不由远程设备直接写入。

---

## 3.9 专注与自我照顾

手机端提供专注状态管理。

触发来源：

- 用户手动开始专注
- 日程进入复习/写代码时间
- 电脑端/平板端报告长时间活跃
- Vela 设备进入专注模式

提醒类型：

- 喝水
- 上厕所
- 看远处
- 晒太阳
- 活动肩颈
- 吃饭
- 结束阶段并记录进度

原则：

提醒应该低摩擦，不应打断强工作流。用户可以延后、跳过或关闭。

---

## 3.10 睡前限制模式

睡前一小时进入限制模式。

手机端行为：

- 降低刺激性通知；
- 不主动推新项目；
- 展示答案箱中的低刺激问题；
- 将高刺激问题推迟到明天或周末；
- 向 Vela 下发睡前卡片；
- 引导每日收束。

Android MVP 提供可选的每日 `HH:mm` 睡前计划。计划由后台闹钟触发，进入
`bedtime` 模式并追加 `ModeChanged`、`BedtimeDeckUpdated`；用户清空时间即可关闭，
不会在未配置时擅自改变当前模式。

睡前模式会暂缓 Buffer 普通事项通知：到期但尚未投递的提醒保持原计划，不记为
已发送；每个提醒修订只追加一次 CardReminderDeferred（reason=bedtime）。进入
睡前模式时撤下已有事项通知，已经发送的提醒退出后不重复提示。退出后恢复
未投递计划；期间完成/归档或改为稍后的提醒仍按取消处理。暂缓期间不为普通
提醒安排反复唤醒闹钟，应用重开或模式切换时重新核对。此行为仅作用于 Buffer
事项通知，不修改系统勿扰或其他应用的通知。手机界面明确显示暂缓状态。

睡前模式不应变成“又一个兔子洞入口”。

---

## 3.11 每周总结与兔子洞

每周生成：

- 本周 Sparks
- 本周未解问题
- 反复出现的主题
- 完成事项
- 拖延事项
- 身体/睡眠/运动/饮食概览
- 下周建议
- 1–2 个兔子洞候选

周报是反思工具，不是 KPI 工具。

Android MVP 提供“生成本周总结卡”入口。每个本地自然周最多生成一张
`weekly_card`，内容来自最近 7 天的物化统计和兔子洞候选，并追加
`WeeklySummaryGenerated` 事件；它可以在生活记录和睡前卡片中回看。

最近七天统计使用闭区间 `[生成时刻 - 7 天, 生成时刻]`。完成事项按
`CardActionPerformed` 的完成时间统计不同任务，旧任务在此期间完成也计入，
重复完成操作不重复计数。新操作事件记录操作时的卡片类型；旧事件缺少类型时
按现存卡片类型回退。未解问题及问题类兔子洞候选排除已回答、已研究、已完成
和已归档的问题。既有周总结卡仍作为生成时快照保留，不因新统计口径自动改写。
重复主题的本地实现按非周报卡片的标签分组，同一原始 Capture 派生的卡片仅算
一条独立记录；至少两条记录出现的标签才展示，最多五项。未标注标签的语义
相似内容不自动认定为同一主题。

拖延回顾展示最近七天至少执行两次“稍后”且当前仍未完成/归档的待办，最多
五项，按延后次数优先；事件 action_id 去重，不把网络重试算成新的延后。
它说明用户的操作记录，不推断拖延的心理原因。

下周建议最多三条：最多两个反复延后事项建议拆成小步骤或重新取舍，加一个
兔子洞候选建议留少量探索时间。建议带来源卡片 ID，写入周总结事件快照；
不会自动创建待办、写入日历或启用探索任务。没有依据时不增加重点。
生活概览展示最近七天已确认 care_card 的身体感受、睡眠、运动、饮食、饮水、
情绪、学习/专注、静心练习、旅行与地点、其他生活记录。每类显示独立记录数、按本地日期计算的
记录天数及最近两条内容；同一 Capture 的派生卡去重。尚未确认的生活分类单列
待确认数量，任务/问题不作为已经发生的健康记录。空分类显示“暂无记录”，
不推断该活动未发生。周总结事件保留来源卡片 ID、天数和示例快照。

当前这是 Buffer 本地文字记录概览，未读取外部健康平台，也未推算睡眠总时长、
运动总量、营养或身体指标；这些量化能力仍待实现。

自动周回顾默认启用，每周日当地时间 20:00 生成，面板开关可关闭。首次启动或
重新启用从下一次计划开始；调度时间持久化，应用重开/启动广播恢复，设备长时间
离线后只补最近到期的一期，不连续补历史周报。时间/时区变化广播会重算闹钟；
切换时区时按新时区安排下一次。使用非精确后台闹钟，系统限流可能延后；被强制
停止后需重新打开应用。自动生成不新增通知，手动入口保持可用。

同一本地自然周手动/自动共享唯一卡片 ID，已有周报保持快照；数据库事务覆盖
查重、统计、卡片和生成事件，生成失败时调度不前进，可重试。补生成根据截至
计划时刻的时间窗口及当前可用物化视图，不宣称能重建完整历史状态。

# 4. openvela / Gemini-S1 设备端文档

## 4.1 设备定位

openvela Gemini-S1 设备是 Buffer 的边缘展示架和语音入口。

它负责：

- 显示少量 Buffer 卡片；
- 通过物理按钮快速录音；
- 本地缓存待上传录音；
- 展示专注/睡前提醒；
- 接收手机或 Coordinator 下发的显示内容；
- 上报设备状态与用户轻量操作。

它不负责：

- 完整 LLM 调用；
- 完整事件簿管理；
- 复杂 CRDT 合并；
- 跨设备主节点选举；
- 写入手机系统日历或健康数据；
- 大型检索和知识库。

---

## 4.2 硬件与约束

目标设备：Gemini-S1 / Allwinner R528 / 双核 Arm Cortex-A7 / openvela。

工程约束：

- 算力有限，不能假设可运行大模型；
- 内存和存储有限，必须控制本地队列大小；
- UI 应以轻量卡片为主；
- 网络断开时仍必须能录音并缓存；
- 按键反馈必须快；
- 同步失败不能造成原始录音丢失。

---

## 4.3 Vela 端核心功能

### 4.3.1 按键语音输入

基础交互：

```text
长按按钮：开始录音
松开按钮：结束录音
```

可选交互：

```text
单击：开始录音
再次单击：结束录音
长按：取消 / 快速录音
```

录音状态必须有明确反馈：

- idle
- recording
- saving
- pending_upload
- uploaded
- failed_retrying

录音完成后生成：

```json
{
  "type": "capture.created",
  "capture_id": "...",
  "device_id": "vela-gemini-s1",
  "created_at": "...",
  "mode": "normal|focus|bedtime",
  "audio_format": "pcm16/wav",
  "duration_ms": 8200,
  "blob_ref": "local://..."
}
```

---

### 4.3.2 离线缓存

Vela 设备必须保证断网时可继续录音。

要求：

- 录音先写入临时文件；
- 文件完整后再登记 pending queue；
- 上传成功并收到 ack 后才能删除本地音频；
- 队列满时提示用户，而不是静默丢弃；
- 重启后继续上传未完成记录；
- 每条 Capture 有唯一 ID，避免重复上传造成重复事件。

---

### 4.3.3 展示架卡片

Vela 设备只显示少量卡片。

卡片类型：

```text
spark_card       灵感卡
question_card    问题卡
answer_card      简答卡
task_card        待办卡
care_card        自我照顾卡
weekly_card      周回顾卡
status_card      设备状态卡
```

卡片字段：

```json
{
  "card_id": "...",
  "kind": "spark_card",
  "title": "意识与现实之间的缓冲区",
  "summary": "Buffer 的核心隐喻。",
  "state": "cooling|recall|done|gray",
  "actions": ["archive", "later", "rabbit_hole"]
}
```

Vela 不需要展示长文本。长文本应在手机、平板或笔记本打开。

### 4.3.4 卡片操作

支持少数操作：

- 下一张
- 上一张
- 归档
- 稍后再看
- 标记为兔子洞候选
- 标记已完成
- 重新提醒
- 进入/退出专注模式
- 进入/退出睡前模式

卡片操作上传为事件：

```json
{
  "type": "card.action",
  "device_id": "vela-gemini-s1",
  "action_id": "act-...",
  "card_id": "...",
  "action": "later",
  "created_at": "..."
}
```

手机返回 `display_cards.updated` 时会携带当前手机模式。Vela 在没有本地未确认
`mode_id` 时采用该模式并刷新本地计时；Vela 自己发起的模式切换则先等待手机对
`mode_id` 回执，再接受手机返回的模式，避免两端短暂断线时互相覆盖。

## 4.5 Vela 与手机/主设备同步协议

### 4.5.1 连接策略

#### 统一添加设备：配对与配网合并

用户确认的交互要求：手机端只提供一次“添加设备”流程，不能要求先在 Vela 上手工配网，再返回手机重复配对。

目标流程：

1. 尚未配置的 S1 进入添加设备模式，发送可连接 BLE 广播；手机按 Buffer 服务 UUID 发现设备，不要求 S1 已连接 Wi-Fi。
2. 用户选择设备，通过 S1 屏幕显示的验证码确认设备，并建立经过认证的加密配置通道。验证码不放进广播，不以设备名称或蓝牙地址作为可信身份，也不直接用六位码作为 Wi-Fi 密码加密密钥。
3. 在同一向导中填写 Wi-Fi 名称和密码。手机通过配置通道提交网络参数，同时建立持久设备身份与业务配对凭据；之后不得再次要求输入配对码。
4. S1 自行连接 Wi-Fi，通过蓝牙返回连接进度、失败原因和结果。密码错误时留在当前步骤重试，不要求用户重新发现和配对。
5. 手机在局域网确认连接的是刚刚认证的同一台设备，验证双端凭据持久化及业务握手后显示“添加成功”，自动开始卡片与录音同步。只有 Wi-Fi 连上时不能提前报告完整添加成功。

已配置 Wi-Fi 的 S1 也走同一个添加入口，可选“使用 S1 已保存的 Wi-Fi 并添加”跳过网络参数填写。设备会用原配置重新关联并获取地址确认可用性，因此可能短暂重连；不重写已有网络凭据。手机负责配置交互，S1 保存配置并独立联网；关闭手机不会使 S1 丢失 Wi-Fi 配置。

配置会话应有期限、错误验证码限流、取消和断连恢复；重复提交应幂等。已经绑定的设备不允许附近陌生手机直接覆盖主人身份或网络配置，重新添加/换网需要已有信任或设备端显式授权。添加成功后关闭未绑定配置入口，日常重连不重复配网。

实现状态：Buffer 已接入 BLE 可连接广播、认证 GATT 配置服务，以及 Android 扫描、系统验证码、Wi-Fi 表单和联网/业务认证双确认流程。Android 会话由 Activity ViewModel 持有，列表项销毁或旋转重建不主动断开 GATT；退出 Activity 关闭连接，密码仅保存在内存。源码、模拟传输和本地数据库测试已通过，蓝牙认证能力和实际 S1 行为仍需实机验证。设备已保存绑定但手机丢失最终 BLE 结果时，已接入认证 LAN 回执恢复；换网/重新授权仍未闭合。设备把 enrollment_id 与手机身份/令牌一起保存，IP 更新保留回执；手机只接受匹配当前未取消请求的有效证明，不能凭明文回执完成添加。现有 UDP/TCP 局域网配对只适用于设备已联网，不能作为首次配网发现通道。NSH 配网命令保留为调试/恢复入口。

第一版建议：

- Wi-Fi 局域网连接；
- 手机/笔记本作为 server 或 peer；
- Vela 作为轻 client；
- 支持断线重连；
- 支持简单设备配对 token。

后续可以接入完整 personal mesh。

### 4.5.2 上传 Capture

流程：

```text
Vela 录音
→ 本地保存 audio blob
→ 创建 capture.created metadata
→ 上传 metadata
→ 上传 audio blob
→ 等待主设备 ack
→ 标记 uploaded
→ 按策略删除或保留本地副本
```

### 4.5.3 接收卡片

流程：

```text
手机/Coordinator 生成 display cards
→ 下发 DisplayCardsUpdated
→ Vela 替换当前 deck
→ 用户浏览或操作
→ 操作事件回传
```

### 4.5.4 Ack 与幂等

所有上传事件必须幂等。

同一个 `capture_id` 重复上传，主设备应返回相同 ack，不应生成重复 Capture。卡片操作必须携带持久化的 `action_id`，模式切换必须携带持久化的 `mode_id`；手机保存两类回执，若 ACK 丢失后收到同一个 ID，只返回原结果，不重复生成 `CardActionPerformed` 或 `ModeChanged`。

# 7. 当前最小闭环

最小闭环不要从完整架构开始，而是：

```text
Vela 按键说一句话
→ Vela 本地保存音频
→ 上传手机
→ 手机转写/分类
→ 手机生成一张 Spark Card
→ 下发给 Vela
→ Vela 展示这张卡
→ 用户按键“稍后再看”
→ 手机收到 card.action
```

这个闭环跑通后，Buffer 的“意识碎片落入现实、再从现实回流”的核心体验就成立了。

### 卡片“稍后再看”的回流规则

当前 `later` 在手机显示为“稍后再看…”，打开明天 09:00、周六 09:00、自选日期时间
的选择器。周六预设取最近尚未到达的周六 09:00，已过则取下周。自选时间在保存前
显示日期、时间和时区确认；取消不写入，过去时间及夏令时重叠/缺失时刻被拒绝。
Vela 现有“稍后”按钮默认选择手机当地次日 09:00。共用回流逻辑持久化绝对到期时间
和原卡片状态；修改计划保留原状态。之后
切换时区不重算已确认的单次到期时间。延后卡片暂时退出日常、专注、探索和睡前
展示队列，仍可从对应归档分类页面查询；Vela 下一次成功同步取得更新后的队列。

后台轮询及非精确闹钟到期后恢复原状态，追加 `CardResurfaced` 并在对应展示队列
优先显示，不修改原始 Capture。完成/归档或其他改变状态的操作取消该计划；
重放同一 action_id 不重复安排。应用重开后处理已到期记录，系统限流可能延迟；
没有独立新增通知。旧版没有到期时间的 later 记录不推断日期、不自动迁移成闹钟。
自选日期和周末回流已接入手机 UI。

### 卡片定时提醒

`remind` 在手机使用同一时间选择器，提供一小时后、最近周六、自选日期时间；
Vela 的默认提醒时间是一小时后。提醒与稍后回流不同：卡片保留在展示队列，
到期通过独立“Buffer 事项提醒”通知频道提示。通知点击直接打开对应卡片详情，读取当前数据库内容及状态；已完成/归档项只读，
不存在时显示缺失提示。活动事项可完成、稍后或重新设提醒，仍需明确点击操作。
每张卡片使用独立 PendingIntent URI，不在跳转 Intent 中复制正文；详情支持旋转恢复。权限或频道被禁用时计划保留，按一分钟间隔重新检查，不追加已发送
事件；手机保存时若全局通知禁用会提示用户在系统设置授权。

数据库保存到期时间、修订号、发送/取消状态及重试时间；重开可恢复。完成、
归档、改为稍后或改变状态会撤销待发送提醒，调度器还会移除已有通知。改期会
替换原计划。重复 action_id 不重复安排。发送使用稳定的卡片通知 tag，成功
后才追加 `CardReminderPosted`，它仅表示提交系统，不表示用户已阅读。
通知与 SQLite 无法跨系统原子提交：发送后写回失败可能再次提交同一 tag，
以替换现有通知和 onlyAlertOnce 减少重复，不能保证绝对只提示一次。
真实后台/Doze 投递及通知点击体验仍需实机验收。

### 配网最终结果丢失的 LAN 恢复

新固件在 hello_proof 中可附带 enrollment_id（32 位小写十六进制）和
 enrollment_proof（64 位小写十六进制）。证明为 UTF-8 令牌作为密钥的 HMAC-SHA256，
消息是 `buffer-enrollment-v1:<server_nonce>:<vela_id>:<phone_id>:<enrollment_id>`。
它使用当前连接的新鲜挑战及独立角色前缀，与普通设备/手机证明分离。

手机先验证普通握手，再验证附加证明；只有 SQLite 中当前请求 ID、令牌均匹配且
未取消，才在同一事务补齐 network_ready/lan_verified、写正式绑定和配对事件。
没有有效回执时仍要求 GATT 联网确认与 LAN 认证两个条件。回执恢复只证明已成功
提交的配网请求，不允许重设主人或修改 Wi-Fi。该扩展不提供业务报文加密。

配置提交后 BLE 断开，客户端在原总超时内等待 LAN 恢复；进程重开后保留的未取消
记录也可由桥接服务接收回执完成，添加页刷新已绑定列表。前提是 LAN 桥接服务
运行、两端网络可达。手机显式取消后不接受恢复，旧固件无回执不能采用此路径。

### 复用已保存 Wi-Fi 的配置请求

认证 GATT 通道允许 `buffer.bind` 请求，字段严格为 type、protocol=1、request_id、
phone_device_id、token；SSID 和 password 必须缺省，混入网络参数拒绝处理。
原 `buffer.configure` 仍严格要求 SSID/密码。两者共用分片、请求去重、会话期限、
Wi-Fi 工作线程、结果分页及认证 LAN 回执恢复。bind 使用设备已有网络配置重连，
只有成功获取地址且会话有效才保存绑定；失败不保存主人，允许改填新 Wi-Fi 并
使用新请求 ID 重试。不代表已绑定设备允许陌生手机覆盖主人或更换网络。

### 待完成设备的恢复与取消入口

添加设备页展示未取消的待添加记录及联网确认状态，列表使用不含令牌的投影。
“继续等待连接”先核对当前请求，再启动 LAN 桥接服务；新 Android 缺少局域网
权限时请求该权限，不因继续等待额外要求 BLE 扫描权限。认证回执完成正式绑定
后刷新为已添加。已取消/被替换的旧请求不能通过该按钮重新激活。

“取消这次添加”按设备和请求 ID 条件撤销授权；若另一线程已提交正式绑定，
提示已添加且不撤销正式绑定。未完成配置的 S1 仍需重新扫描，不把等待连接当作
重新配网。取消不等于清除 S1 上已经保存的 Wi-Fi 或正式主人信息。

### 手机端兔子洞研究会话

模式区“开始兔子洞研究”允许选择尚未完成/归档的问题、灵感或兔子洞卡片，再选择 60、90、120 分钟。开始后切换到深挖模式，显示主题和剩余分钟；保存绝对截止时间，重新打开手机应用不重置计时。仅切换“深挖”模式不会擅自选择主题或开始研究。

用户可提前结束并保存最多 4000 字的研究笔记。到期自动结束并回到普通模式，不把主题卡自动标记为已研究或已回答；切换其他模式时结束本次会话并保留新模式。最近一次结束的会话可补充笔记，开始新会话后旧记录仍在事件簿中。“历史研究记录”从事件簿合并每次会话的最新快照，按最后记录顺序分页，每页 20 条。可查看开始时间、计划/已记录分钟、结束原因与最终笔记，并打开仍存在的原主题卡片；开始新会话不删除旧记录。历史页面当前只读，补记仍针对最近一次已结束会话。

会话、模式及开始/结束事件使用同一个数据库事务；过期会话 ID 无权结束新会话。后台使用非精确闹钟和进程内轮询，应用重开也执行到期检查；设备休眠可能推迟处理。截止时间采用设备墙钟，用户改系统时间可能影响显示的剩余时间。到期通知使用独立“Buffer 研究计时”渠道，点击打开 Buffer。通知权限或渠道关闭时保留待送达状态，每分钟重试；睡前模式暂缓并撤下已有通知，退出只补发尚未送达的通知。手动结束或切换模式结束不新增到期通知；开始新研究清除旧待提醒状态。每周日历预约及 Vela 端研究计时界面仍待实现。
