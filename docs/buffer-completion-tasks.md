### 01 普通模式卡片组合（2026-10-23）

实施前比较了独立源仓库与参赛快照的 `BufferRepository.kt`：独立仓库 Android Buffer 为 9 月版本，缺少当前项目的 processed capture、专注、日历 CRDT 等集成。此项修改参赛项目的现行应用，不将其覆盖回独立框架仓库，也不改框架。

- 手机入口：`MainActivity.refresh` 统一调用 `cardsForMode`；normal 使用 `normalCards` 遍历全部符合条件的 SQL 行。按灵感、今日待办、问题/答案各保留一个名额；类内按 returned_at、created_at、稳定 card_id 排序，剩余名额由同样顺序的近期记录补齐。不存在的类别不伪造占位，小容量按上述类别顺序取，非正容量返回空。
- “今日”由当前本地时区的日界线与明确 schedule 的重叠决定，包含跨日事项及 DST 日；无明确 schedule 的任务仍可填充卡组，不把捕获当天冒充任务日期。
- Vela：新增 `buffer_deck.h`，副本扫描和 Agent 本地记录/旧缓存合并共用有界候选池。类别冠军独立于最新五条保存，避免最新记录挤掉罕见类别；按稳定 ID 去重。现存手机副本（包括墓碑）继续优先于同 ID 本地记录。
- `displayCardJson` 在旧 LAN 卡组和新 CRDT 文档中携带 schedule 及 `display_return`。`buffer_wire.c`、`buffer_replica.c` 读取元数据，`buffer_store.c` 保存并恢复；旧消息/旧缓存缺字段按零值兼容。元数据仅用于展示，不创建通知、提醒或日历副作用。
- 排除完成、归档、删除、未转写卡片，继续隐藏已有稍后计划。手机记录只在手机完成回流后恢复；Vela 本地未导入记录到期时采用其原状态和到期时间进行展示投影，不改写 processed capture 或伪造远端回执。
- 回顾中补齐了离线刷新：Agent 的独立短轮询负责日期/时区/模式变化及本地稍后到期，刷新不再依赖 Wi-Fi/模型成功。无变化时不扫描文件；分配或存储失败保留已保存卡组并允许后续重试。副本目录按有效文件扫描，未使用包含 ACK 辅助文件的 readdir 数量截断。

静态回顾覆盖生成→下发/复制→解析→缓存→重启读取→离线重建→首页展示，以及零容量、空类别、去重、DST 日界线、模式切换和分配/保存失败。未运行测试或构建，设备性能与实际行为仍属单列验收项。

### 02 Vela 研究会话显示（2026-10-23）

- 核对了 Android `rabbitSnapshot` → Fabric `buffer.runtime.state` / LAN `display_cards.updated` → `buffer_parse_research` → `buffer_sync_research` → `buffer_research_snapshot`：原链路已接收真实会话，缺少最终 UI 调用。
- 在 `buffer_ui.c` 的 Buffer 页可滚动正文内、记录卡片之前添加研究面板。现有 500ms UI 刷新读取内存快照，显示主题、剩余分钟、时间到、已结束或已中断；无会话时隐藏。复用单调时钟，不因断连暂停或重置；没有新增模型请求、伪倒计时、强制切页或完成待办副作用。
- 模式门禁沿用 domain：待确认本地模式切换、专注、睡前隐藏；活动会话只有深挖模式显示，已结束会话可在普通模式回看。仅手动切到深挖且没有会话时不虚构主题。

- 面板随屏宽自动换行，可随正文滚动；录音按住期间延后更新，录音入口仍独立固定。没有新增计时器或异步 LVGL 回调；在 owner-thread 刷新，关闭原刷新计时器后由 root 统一删除，指针归零。
